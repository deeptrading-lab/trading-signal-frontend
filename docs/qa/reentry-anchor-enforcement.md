## 3. 설계 교정 — 프롬프트와 서버 규칙 불일치

dry-run 중 발견: 기존 프롬프트 문구는 *"아래에 받쳐줄 매물대가 **없으면** null"* 이라 **총공백만** 다루는데, 서버 규칙은 *"매물대 **안에** 있어야 한다"* 는 더 엄격한 조건이었다. 이 상태면 PM 이 프롬프트를 지켜도 서버가 무효화해 **준수율 측정이 오염**된다.

어느 쪽이 맞는가 — 사용자가 정의한 논리는 *"아직 매물대가 더 아래에 있으면 해당 박스권 가격까지는 더 하락 위험이 있는 것이고, 이미 지지대 근처면 매수 타이밍"* 이다. 삼성전기 사례(재진입가 1,002,800원인데 실제 매물대는 944,500원 = 아직 5.8% 하락 여지)가 정확히 이 케이스이므로 **서버 규칙이 맞고 프롬프트가 느슨한 것**. 프롬프트를 서버에 맞춰 교정했다(매물대보다 위·아래 모두 틀렸음을 명시 + 서버 검증 사실 고지).

## 4. 소급 적용(dry-run) — 문제의 크기

과거 약세 판정 중 재진입가를 제시한 38건에 규칙을 소급:

```
앵커 통과 21 / 무효화 17  → 45%
```

⚠️ **이 45% 는 규칙 위반율이 아니다.** 38건 전부 앵커 규칙(#375) 도입 **이전** 판정이고(규칙 이후 약세+재진입가 표본은 0건이었다), 레벨은 오늘 시점 일봉으로 계산해 결정 시점과 창이 어긋난다. 문제의 크기를 가늠하는 용도로만 읽어야 한다.

## 5. 범위에서 뺀 것 (근거 기록)

- **약세 무효화 라인(stop) 앵커** — 소급 점검 결과 15건 중 9건이 이미 저항 매물대에 앵커돼 있고, 어긋난 경우도 가장 가까운 저항과의 거리 중앙값이 2.3%p 였다. 재진입가(45% 어긋남)와 문제의 크기가 다르므로 이번 범위에 넣지 않는다.
- **원거리 매물대 상한** — SK하이닉스는 가장 가까운 지지가 −35% 라 "앵커됨"으로 통과하지만 실용적 재진입가가 아니다. 상한(−20% 초과 null) 도입은 표본이 더 필요하다.

## 7. 잔여 리스크

1. **텍스트·숫자 불일치 가능성** — 서버가 `target_pct` 를 null 로 만들어도 `new_entry_strategy` 텍스트엔 무효화된 가격이 남을 수 있다. 차트 오버레이·터치 채점을 구동하는 **권위 있는 숫자**를 제거하는 게 우선이라 수용하되, `target_pct_voided_reason` 발동률을 보고 잦으면 카드 표기("재진입가 미제시 — 아래 지지 공백")를 후속으로 붙인다. 이번 라이브 3건에선 모델이 규칙을 지켜 텍스트도 일관됐다.
2. **발동 경로가 라이브에서 관측되지 않았다** — 0건 발동은 좋은 신호지만 실제 무효화 동작은 단위 테스트로만 확인됐다.
3. **레벨은 결정 시점 일봉 기준** — 재개(resume) 실행에서 일봉을 다시 받으므로 프롬프트 주입값과 검증값은 항상 동일하다(같은 `priceLevels` 객체 재사용).
