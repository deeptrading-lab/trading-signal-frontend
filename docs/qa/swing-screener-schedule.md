# QA — swing-screener-schedule (스크리너 예약을 자정 이후 매시로)

- 실행: 2026-11-02 10:00~10:20 KST
- 대상: 브랜치 `feature/swing-screener-schedule`
- 근거: `docs/prd/swing-judgment.md` §9 OQ-1(2026-11-02 변경)

## 문제(실측)

| 항목 | 값 |
|---|---|
| `score-decisions` 예약 | `10 8 * * 1-5`(08:10 UTC) — 10-18 이후 그대로 |
| 실제 시작 | 10-19~10-30 매일 13:21~15:33 UTC — **5~7시간 늦음** |
| `swing-screener` 11-02(월) 예약 3회 | 22:20·23:20·00:20 UTC(07:20·08:20·09:20 KST) — 09:54 KST 까지 **하나도 시작 안 함** |

같은 지연이면 07:20 예약 스크리너가 점심 무렵에야 돌아 장 시작 전에 목록이 없다.

## 변경

- 예약: `20 16-23 * * 0-4`(01:20~08:20 KST 매시, 월~금) + `20 0 * * 1-5`(09:20 KST). 처음 끝까지 돈 1회만 처리하고 나머지는 route 가 `skip:"done"` — `concurrency.cancel-in-progress: false` 라 늦게 온 트리거가 진행 중인 실행을 끊지 않는다.
- 입력 불변: 거래일 t = 오늘(KST) 이전 마지막 거래일 — 01:20 에 돌든 07:20 에 돌든 같은 전 거래일 확정 데이터. 토요일 새벽(금 UTC)은 예약하지 않는다(`0-4`), 금요일 데이터는 월요일 새벽에 처리(기존과 같음).
- 새벽(07시 전 KST)에 한 구간이 3회 실패하면(KIS 야간 점검 가능 시간) 실패 대신 성공 종료 — 다음 예약이 이어서 처리하고, 매일 실패 메일이 오지 않게. 07시 이후 실패는 그대로 실패.
- 호출량 불변: 하루 전체 처리 1회(KIS 약 7천 콜). 나머지 트리거는 완료 마커 확인 1회 뒤 종료.
