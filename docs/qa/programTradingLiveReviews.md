## 실행 기록

- `npm run test -- lib/server/programTrading/__tests__`: 최종 통합 담당 실행 기준 71테스트 통과·타입검사 통과. 기획자 직접 실행한 직전 검증은 10파일 60테스트 통과였다. 초기 계좌테스트의 과거 replay 기대값 오류는 prod 계약으로 수정 후 재검증했다.
- fake broker 엔진 17건과 WAL 3건 포함. 실제 주문·취소를 한투 서버에 전송하지 않았다.
- 실제 계좌 조회 전용 검사에서 accountComplete·feesNumeric·ordersComplete 및 tradingDay=false를 확인했다는 통합 담당 결과를 반영했다. 조회 스크립트는 account/orders/session만 호출하고 식별자·비밀·금액을 출력하지 않는다. 휴장일이라 실제 주문 접수/부분체결/취소·장중 시세·실제 최종 정산·장시간 운용은 미검증이다. 빌드/브라우저 최종 결과는 통합 QA 기록을 따른다.
- 계좌 입출금 감지는 실제 일자별 비용 차감 후 종료자산과 거래대금 차이가 1원을 초과하면 잠금 처리한다. 비용 미조회시 정산하지 않는다. 서로 상쇄되는 외부 입출금을 완전히 분리한 거래 회계로 해석하지 않는다.

## 영속성 추가 검증

`liveStore.test.ts`는 기존 truncated tail/last synced intent 테스트를 유지하고 corrupt complete line failclosed, broker credentials 미복사 검증을 추가하여 3건 통과했다. 네트워크를 사용할 수 없는 fake broker만 사용했다.

## 최종 통합 변경 재검수

- 계좌 BFF의 GET/POST 모두 worker로 위임한다. 계좌 검증·broker 시작은 자격증명 해시별 shared transport를 사용하여 같은 프로세스의 불필요한 토큰 중복 발급을 줄인다. 비밀 원문은 로그에 기록하지 않는다.
- 시작 전 보유 검사는 비6자리 자산 코드와 소수 수량도 보유로 남긴다. 음수 수량·가격은 필터링 전에 거부한다. 기존 자산이 숨겨져 빈 계좌처럼 시작되는 것을 방지한다.
- `program:resolve`는 worker와 같은 포트 잠금을 확보하며 운용자가 명시한 client-id·broker-order-id·date와 `--confirm-broker-order=yes`가 필요하다. 의도 생성일, 전체 주문조회, 종목·방향·수량, 이미 연결된 ID 여부를 검증하고 영속 원장에 연결만 기록한다. 가격 자동 매칭이나 주문·취소 전송은 하지 않는다. 재시작 대사가 끝나기 전에는 신규매수를 재개하지 않는다.
- 위 변경은 소스 재확인 후 승인했다. 실제 `program:resolve`로 운용 원장을 변경하지 않았다.
- 최신 실행·복구 방법과 실제 조회 범위는 `docs/program-trading/integration.md` 앞부분이 현재 기준이며, 하단은 과거 합성 전용 기록으로 구분된다.

- 최종 통합: 프로덕션 빌드 통과. 브라우저 데스크톱/390폭 모바일에서 실전 모드·한도·휴장 사유·시작 비활성화를 확인했다. 실제 시작 버튼은 누르지 않았다.
