## DB 및 보안

- 기존 `trading-signal-engine` 프로젝트에 `program_paper_asset_events` migration 적용 완료.
- 브라우저 식별자 지원 migration에서 Google profiles FK만 제거했으며 기존 행과 RLS·서비스 전용 권한을 유지함. 브라우저 해시 식별자로 DB 저장·조회 검증 후 롤백함.
- DB 쓰기/읽기 왕복 12,345,678원 검증 후 롤백. 테스트 데이터는 보존하지 않음.
- RLS 켜짐, anon SELECT 없음, authenticated INSERT 없음, service_role INSERT 허용 확인.
- 서비스 전용 테이블이라 사용자 정책 없이 RLS를 유지한다. [RLS 정책 없음 INFO 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)는 의도된 서버 전용 접근이며 공개 권한은 없다.
- 브라우저에 서버 키나 선택 가능한 소유 계정을 전달하지 않음. 기본정보 조회와 자산 저장은 BFF 경유.
- 기존 공용 원장의 소유자는 추정하지 않음. 새 계정 원장과 다운로드·로컬 복기를 분리함.

## 검사와 한계

### 자산 설정 UI 정렬 개선

- 실제 localhost 화면 1280×900에서 요약·폼 제목 상단 차이 0, 입력·저장 버튼 높이 각 40, 아래 기준선 차이 0 확인.
- 390×844에서 입력·저장 버튼 너비 각 362, 세로 배치 및 가로 넘침 없음 확인.
- 자산 설정 링크는 운용 손익 영역 안에 한 개만 배치되며 SVG 아이콘 포함·테두리 0 확인. 링크 클릭으로 설정 화면 이동 확인.
- UI만 변경했으며 금액 저장이나 자동매매 실행은 하지 않음.

- 자동매매·자산·인증·BFF 관련 119개 테스트 통과. TypeScript 및 변경 파일 ESLint 통과.
- DESIGN.md lint errors=0, warnings=0. 기존 토큰을 재사용하며 새 색·간격 토큰은 추가하지 않음.
- 프로그램 규칙 다이어그램 재생성·일치 검사 및 실제 Chrome 종료·DB 저장 다이어그램 검사 통과.
- 실제 UI 검증에는 임시 로컬 모의 API를 사용하여 운영 DB 자산을 변경하지 않음.
- 로컬 Google OAuth 및 APP_AUTH_SECRET 없이 브라우저 지속 키를 사용한다. Google 로그인에 대한 환경 설정은 필요 없다. 배포 환경의 로그인 게이트는 기존 proxy 회귀 테스트로 유지 확인.
