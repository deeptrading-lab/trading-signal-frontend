# 로컬 프로그램 자동매매 QA / 지속 오답노트

## 실행
- 2026-10-27, feature/local-program-trading
- `npm run dev -- --hostname 127.0.0.1` → http://127.0.0.1:3000/intraday
- `npm run program:worker` → 127.0.0.1:4318 (로컬 전용)
- 중지: 화면에서 신규 매수 중지(보유분 관리 지속) / 전량 청산·중지. 프로세스 종료는 터미널 Ctrl+C.
- 상태: `.local/program-trading/state.json`; 자동 복기 원장: `.local/program-trading/review.md`. 재시작 시 신규매수 중지로 복원. 단일 가상 거래일이며 15:20 이후 새 실험은 워커 종료 후 상태 파일을 별도 보관하여 새로 시작.

## 독립 에이전트 검수와 수정
트레이더: stale/halt 허위 청산 → 공통 유효성 검사로 청산 보류. 비용 제외 위험 수량 → 비용 포함 수량. Markdown 줄바꿈 수정. 실계좌 주문/부분체결 대사 필요는 후속 과제.
UI: 엔진 lastError 노출 및 신규시작 차단. 종료 상태 안내. 없는 폰트 토큰 교체. 모바일 hit-area-min 적용. 두 에이전트 모두 코드 검수, 실행 화면은 주 에이전트가 모바일에서 확인.

## 성능 판단
3개 합성 종목 111,300회 규칙 평가: 이 로컬 환경에서 163ms, 평균 약 1.47μs/평가. 워커 I/O·브로커 지연·네트워크·실데이터 부하를 제외한 마이크로벤치마크이며 실매매 지연 보장이 아니다. 수초 단위 전략은 TypeScript/Node로 적합. 대규모 백테스트와 학습은 Python 별도 프로세스 권고.
근거: https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop 및 https://github.com/koreainvestment/open-trading-api
