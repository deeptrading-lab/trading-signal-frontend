### 5-1. 레짐 veto 상시 무력화 (부수 발견)

`computeRegime` 은 `SMA120[i-20]` 을 참조하므로 **최소 140봉**이 필요하다. 200일 창은 134봉이라
**모든 종목에서 `regime = 0`(중립)으로 고정**되어 약세 레짐에서 BUY 를 막는 veto 가 상시 미적용
상태였다. 365일 창에서 실제로 살아나는 것을 확인:

```
두산에너빌리티  200일: bars=134 regime=0 SELL/36   →   365일: bars=244 regime=-1 SELL/36
SK하이닉스      200일: bars=134 regime=0 SELL/31   →   365일: bars=244 regime=0  SELL/31
삼성전자        200일: bars=134 regime=0 SELL/37   →   365일: bars=244 regime=0  SELL/37
```

표본 3종목은 4축 판정이 이미 SELL 이라 veto 대상이 아니어서 score 는 불변(무회귀 확인).
regime 이 실제로 계산되기 시작한 것은 두산에서 확인됨(0 → -1).

### 5-2. 52주 고저 라벨 정합

`formatPriceContextForPrompt` 의 52주 고저는 `candles.slice(-252)` 인데, 200일 창에서는 134봉밖에
없어 **실질 6.5개월 고저를 "52주" 로 표기**하고 있었다. 365일 창에서 244봉이 되어 라벨이 제 값을 찾는다.

## 8. 잔여 리스크

1. **프롬프트 규칙은 강제가 아니다.** 재진입 앵커 규칙을 모델이 무시해도 런타임에 막히지 않고 사후에만 검출된다. 표본을 늘려 준수율을 관측하고, 무시 빈도가 유의미하면 서버 후처리(공백 구간이면 `target_pct` 를 null 로 강제)로 승격해야 한다.
2. **급등 종목의 원거리 매물대.** SK하이닉스는 아래 지지가 -35%/-42.6%/-50.1% 로 매우 멀다. 이번엔 모델이 "지지" 가 아닌 "공백" 으로 올바르게 해석했으나, 거리 상한(예: -20% 초과 시 null) 도입 여부는 표본을 더 보고 판단할 사안.
3. **레짐 veto 재활성화는 판정 분포를 바꿀 수 있다.** 표본 3종목에서는 무회귀였으나, 4축이 BUY 를 내는 약세 레짐 종목에서 처음으로 veto 가 발동하게 된다. 이는 의도된 안전장치의 복구이지만 분포 변화이므로 머지 후 관측 대상.
4. **KIS 조회 청크 증가.** `fetchDailyChunked` 100봉 분할이 2회 → 3회. 분석 1회당 수백 ms 수준.
