## 0. 문제 정의

- DART `company.json`(현 `lib/api/dart/company.ts`)은 **대표자·주소·업종코드·설립일**만 제공 — **자유 텍스트 사업 설명 없음**.
- KIS `search-stock-info`/`inquire-price`도 업종명까지만(이미 #92에서 반영). 사업 내용 텍스트 없음.
- 따라서 "무슨 사업을 하는 회사" 한 문단은 **별도 출처**가 필요.
- 제품 톤(토스): **짧고 읽기 좋은 한 문단**(2~4문장)이 이상적. 긴 원문 통째 노출은 비선호.

## 2. B 후보 — FnGuide/wisereport 실응답 샘플 (3종 교차)

엔드포인트: `https://navercomp.wisereport.co.kr/v2/company/c1010001.aspx?cmp_cd=<6자리코드>`
형식: **정적 HTML**(별도 ajax 없음), `##### 기업개요` 블록 하위 순수 텍스트.

### 삼성전자 (005930) — 약 260자 / 3문장
> 동사는 1969년 설립된 글로벌 전자 기업으로, DX, DS, SDC, Harman 산하 308개 종속기업으로 구성됨.
> DX 부문은 TV, 가전, 스마트폰, DS는 메모리 반도체와 Foundry 사업, SDC는 OLED 패널, Harman은 전장부품·오디오 사업 운영함.
> 동사는 AI 기술 확대, 선단 공정 개발, 고부가 솔루션 포트폴리오로 제품 차별화 및 원가 경쟁력 제고하며 질적 성장에 주력하고 있음.

### 카카오 (035720) — 약 270자 / 3문장
> 동사는 1995년 주식회사 다음커뮤니케이션으로 설립되어 2014년 카카오와 합병, 2017년 유가증권시장에 상장하였음.
> 카카오톡을 중심으로 커머스, 모빌리티, 페이 등 다양한 영역에서 수익을 창출하며, 카카오엔터테인먼트 등을 통해 콘텐츠 사업을 강화하고 있음.
> 카카오톡 플랫폼을 통해 광고, 커머스 비즈니스 툴을 제공하여 파트너 성장을 지원하고, 인공지능 등 미래 기술 연구개발로 혁신을 추구하고 있음.

### 셀트리온 (068270) — 약 234자 / 3문장
> 동사는 1991년 설립된 글로벌 생명공학기업으로, 2023년 셀트리온헬스케어와 합병해 생산·판매 통합 법인 체제를 완성했으며, 2025년 미국 생산설비를 인수함.
> 자가면역질환, 종양 치료 의약품을 개발해 11개 제품의 글로벌 품목 허가를 획득하여 세계에서 판매 중임.
> 자체 R&D와 글로벌 파트너십을 통해 차세대 모달리티 연구개발을 지속하며, 직접 판매망으로 시장 지배력을 강화하고 있음.

**관찰**: 3종 모두 **균일하게 3문장·230~270자·"동사는~" 토스톤**. 차단 메시지 없음, 한글 인코딩 정상. `robots.txt`는 404(명시적 크롤 규칙 없음 — 단, 저작권은 별개).

**리스크**:
- 콘텐츠 저작권 = **FnGuide**(네이버 제휴 표시 데이터). robots 부재가 사용 허락은 아님. 비공개(앱 비밀번호 게이트) 서비스라 노출 범위는 제한적이나 회색지대.
- 비공식 → DOM/엔드포인트 변경 시 깨짐(파서 방어 필요).
- **Vercel(iad1) IP에서 접근 차단 가능성** — [[reference_kis-api-conventions]]의 해외 egress 500 사례처럼 한국 사이트가 해외 IP를 막을 수 있음(KIS 미국지수가 그랬음). **프로덕션 환경 실측 필수**.

## 3. A 후보 — DART 사업보고서 본문 ("사업의 개요")

흐름: `list.json`(corp_code+정기보고서종류 → 최신 사업보고서 `rcept_no`) → `document.xml?rcept_no=<>`(**ZIP 다운로드**) → unzip → 본문 XML/HTML에서 "II. 사업의 내용 > 1. 사업의 개요" 섹션 추출.

- **장점**: 공식·무료(`OPENDART_API_KEY` 보유), 정확. 저작권 명확(공시 공공데이터).
- **단점**:
  - `document.xml`은 **ZIP 바이너리** → Node `adm-zip` 등으로 해제 + `cheerio`/`fast-xml-parser` 파싱 필요. serverless 함수에서 ZIP 처리 부담(메모리·시간).
  - 본문 HTML 구조가 **기업마다 제각각**(섹션 제목·표 혼재) → "사업의 개요" 추출 파서가 취약.
  - 원문이 **수천~수만 자** → 그대로 못 씀. 첫 N문장 트렁케이트 or LLM 요약 필요 → 결국 D로 수렴.
- 결론: 안정 베이스로는 좋으나 "짧은 한 문단" 목표엔 후처리(요약) 필수.

## 4. C 후보 — LLM 생성

- `trading-signal-engine` FastAPI 경유(`analyze`류 이미 존재). 종목명+업종+사업코드를 주고 "무슨 사업을 하는 회사" 2~3문장 생성.
- **장점**: 가벼움, 톤 일관, 저작권 무관.
- **단점**: **환각**(매출 비중·연혁 등 사실 오류 위험) — [[project_read-only-analysis-scope]] 조회·분석 신뢰성과 충돌. FastAPI LLM 연동 존재/비용 미확인.
- 단독 사용 비권장. D처럼 **사실 소스(A)를 입력으로 줄 때만** 안전.

## 6. 권고

1. **1순위: B(wisereport) + 강한 폴백** — 실응답이 목표(짧은 토스톤 한 문단)와 정확히 일치, 구현 가벼움. 단 **프로덕션(Vercel iad1) 실접근 가능 여부를 가장 먼저 PoC 확인**. 차단되면 B 폐기.
   - 폴백: 실패/차단 시 설명 블록 **숨김**(에러 노출 안 함) + 출처 표기("출처: FnGuide") 검토.
2. **B가 프로덕션에서 막히면 → A(DART) + 첫 N문장 트렁케이트** 로 전환(요약 없이도 1차 가용), 이후 여유 시 D로 고도화.
3. **C 단독은 비채택**(환각).
