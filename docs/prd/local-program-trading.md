# 로컬 토스 모의매매

## 1. 문제
실제 주문 없이 국내주식 자동매매 기준과 운용 흐름을 연습할 수 있어야 한다.

## 2. 사용자
본인 컴퓨터에서 토스 Open API 시세 키로 전략을 연습하는 사용자.

## 3. 범위
로컬 `/program-trading`에 토스 시세 기반 가상 계좌와 매매 시작·종료, 가상 보유·손익·원장을 제공한다. 초기 자금은 1,000만 원이다.

## 4. 동작
- `.env.local`의 토스 클라이언트 ID·시크릿을 사용한다. 한투 실전 거래량 순위의 일반주식 상위 14개 중 전일 대비율이 0%를 초과하는 종목만 후보로 사용한다. 수급 순위는 호출·합산하지 않는다. 후보가 없거나 조회에 실패하면 신규 매수를 중지하고, 유효한 후보가 돌아오면 기존 운용을 재개한다.
- `npm run program:dev`로 루프백 개발 서버를 시작한다. 서버 내부에서 단일 엔진이 상태와 원장 반영을 직렬 처리한다. 외부 시세 조회는 명령을 가로막지 않는다.
- 유효한 후보와 정규장 정보를 확인하고 KST 09:10~14:30 미만에 시작한다. 매수 직전 현재가가 후보의 추정 전일 종가를 초과하는지 재확인한다. 최근 완료 양봉의 종가가 이전 3봉 고가를 0.1% 초과하고 거래량 1.5배 이상, 현재가·매도호가가 신호 종가 +0.2% 이하이며 스프레드 7bps·예상 왕복비용 0.4% 한도를 통과하면 가상 체결을 기록한다.
- 최대 1종목·비중 15%·계획 위험 0.1%로 운용한다. 종목 비용 후 −0.8% 손절/+1% 익절, 순익 고점 +0.6% 이후 0.3%p 추적 청산(최소 +0.1%), 최대 보유 5분을 적용한다. 세션 손실 −0.6%, 계좌 비용 후 목표 +1%, 연속 손실 2회, 매수 10회, 30초 시세·엔진 공백과 마감에서 세션을 종료한다. 손실 종목은 같은 세션 재진입을 차단한다. 유효 시세로 우선 청산하고, 종료 요청 후 30초가 지나면 잔량을 마지막 기록 가격으로 가상 정산한다. 종료 자산과 수익률에 반영하고 원장과 화면에 정산 근거를 표시한다.
- 로컬 파일에 상태와 가상 체결 원장을 저장한다. 서버 재시작 시 신규 매수를 멈춘 상태로 복원한다.
- 거래 종료 후 **새 세션 열기**를 누르면 기존 상태와 원장, 복기를 자동으로 보관하고 가상 자금 1,000만 원으로 시작을 대기한다.
- **세션 결과 보기**에서 종료된 현재 세션과 보관된 세션의 자산, 손익, 수익률, 청산 건수와 복기 항목을 확인한다.
- 세션 결과는 원장 대조 결과, 확인된 문제, 기록 부족으로 판단을 보류한 항목, 전략 개선 가설과 근거를 표시한다.

## 5. 수용 기준

- 세션 결과의 첫 콘텐츠에서 최신 AI 판단과 개선 제안을 확인한다. 실제 적용 이력, 상세 지표, 검수와 전체 실적은 이어서 확인할 수 있다.

- 세션 결과 화면에서 저장된 종료 세션의 수익률을 종료 시각순으로 그래프에 표시한다. 각 세션의 수익률과 원화 손익을 확인할 수 있으며, 유효한 기록이 없으면 빈 상태를 안내한다.

1. 토스 키와 앱의 기존 순위 연동을 갖춘 로컬 환경에서 로그인 없이 상태 조회와 시작 명령을 사용할 수 있다.
2. 휴장·장외와 교차 출처 시작 요청을 거부한다.
3. 정상 가상 체결은 유효 시세를 쓰며, 후보 만료 시 신규 매수를 중지한다. 후보 회복 시 제한을 확인하고 다시 매수를 검토한다. 시세·엔진 공백으로 종료된 세션은 자동 재개하지 않는다.
4. 시세 요청이 응답하지 않아도 30초 후 잔량을 가상 정산한다. 가상 보유가 0이면 복기를 생성한다.
5. 결과를 Supabase에 저장하고, 로컬 Codex로 평가한 점수·제안과 커밋으로 확인한 적용 내역을 세션별로 조회할 수 있다. 세션 결과 화면에서도 선택한 세션의 점수·근거·제안·적용 이력을 확인하고, 평가 조회 실패 시에도 로컬 결과는 볼 수 있다.

6. 같은 Supabase 프로젝트에 연결한 다른 PC에서도 공유 DB 목록의 종료 결과와 AI 평가를 열 수 있다. 배포 환경의 결과 조회는 관리자만 가능하다. DB 조회에 실패하면 이 PC에 저장된 결과는 계속 열 수 있다.

## 6. 저장과 접근
`.local/program-trading/toss-paper/`에 가상 거래 기록을 보관한다. 루프백 개발 서버와 동일 출처 변경 요청만 허용한다.
현재 세션과 보관 세션의 `review.json`을 합쳐 최신 100건까지 보관한다. 한도를 넘으면 오래된 결과 JSON부터 제거하며 원장과 상태 파일은 보관한다. Supabase 복기는 선택 기능이며, 결과와 평가·적용 이벤트는 서버 키로만 저장 및 조회한다. 평가가 매매 규칙을 자동 수정하지 않는다.

## 7. 운영
가상 체결은 비용·슬리피지 가정을 사용한다. 설정과 운용 절차는 [시작 가이드](../program-trading/getting-started.md)에 있다.

## 8. 영향 분석
자동매매 BFF는 로컬 엔진을 직접 호출한다. 앱의 다른 메뉴는 각자의 기존 접근 규칙을 사용한다.

## 9. OPEN QUESTION
계정별 접근과 점수 추세 화면은 여러 사용자가 필요해지면 검토한다. 이번 범위에서는 로컬 운용자가 결과 화면과 CLI로 조회한다.

### 평가에서 개선 적용
완료 세션의 최신 평가에서 개선 적용하기를 누르면 로컬 Codex가 근거를 갖춘 한 가지를 임시 작업 폴더에서 구현한다. 운용 중인 세션이 없고, 허용 범위와 자동매매 검증을 통과하며, 같은 파일에 동시 수정이 없으면 작업 폴더에 반영한다. 결과와 실패 사유를 화면에 표시하고 실제 반영 후에만 이력을 저장한다.

후보 단순화의 수용 기준과 2026-11-18 손실 검토는 [거래량 상위 상승 후보 PRD](volume-positive-candidates.md)에 따른다.

현재 실행 규칙은 [짧은 노출 모의전략 PRD](short-exposure-scalper.md)의 `program-v5-short-exposure`를 따른다. 손실·재진입·횟수 제한은 세션 한정이며 새 세션에서 초기화한다. 수익 목표와 손실 임계값은 달성·체결 가격을 보장하지 않는다.
