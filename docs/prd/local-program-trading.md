# 로컬 토스 모의매매

## 1. 문제
실제 주문 없이 국내주식 자동매매 기준과 운용 흐름을 연습할 수 있어야 한다.

## 2. 사용자
본인 컴퓨터에서 토스 Open API 시세 키로 전략을 연습하는 사용자.

## 3. 범위
로컬 `/program-trading`에 토스 시세 기반 가상 계좌와 매매 시작·종료, 가상 보유·손익·원장을 제공한다. 브라우저 고유 키의 직전 종료 자산 또는 최근 수동 저장값으로 시작하며, 저장 이력이 없을 때만 1,000만 원을 사용한다. 세부 동작은 [계정별 자산 PRD](program-account-assets.md)를 따른다.

## 4. 동작
- 평일 09:00~15:00 미만에 시작한다. 09:05 전에는 후보를 조회하지 않는다.
- 토스 국내 시장 실시간 거래량 상위 100개에서 종목 기본정보의 securityType이 STOCK인 기업 주식만 대상으로 한다. ETF·ETN·파생상품·유형 미확인 종목은 제외하며 종목명으로 유형을 추정하지 않는다. 캐시에 없는 종목 유형은 일괄 조회하고 실패하면 신규 매수 없이 다음 후보 조회를 기다린다. 거래량 100만 주 이상이고 전일 대비 상승한 종목을 거래량 내림차순으로 정렬한다. 당일 후보가 없거나 조회에 실패하면 10분 뒤 새로 조회한다.
- 가용 현금을 후보 수로 균등 배분한다. 랭킹 가격으로 살 수 있는 정수 주를 순서대로 가상 매수하며, 잔액은 현금으로 남긴다. 거래 비용은 0이다.
- 보유 종목은 5분마다 일괄 현재가를 조회한다. 매수가 대비 +2% 이상 또는 −1% 이하에서 해당 종목을 전량 매도한다. 보유가 0이면 세션 시작 자산 대비 현금이 +1% 이상 또는 −2% 이하일 때 종료하고, 그 사이면 후보를 다시 선정한다.
- 15:00부터 신규 매수하지 않는다. 5분 시세 점검에서 모든 보유 종목의 유효 가격이 확보되고 전체 평가자산(현금+보유 평가액)이 세션 시작 자산을 초과하면 전량 청산 후 종료한다. 0%·음수이면 기존 종목별 익절·손절을 계속 적용하며 15:30 장 마감 또는 수동 종료 시 수익률과 관계없이 전량 청산한다. 현재가를 받을 수 없는 종목은 마지막 유효 기록가로 정산한다. 모의매매 토스 요청은 최소 60초 간격으로 전송하고 429 요청을 폐기한다.
- 화면은 후보, 운용 손익, 가상 보유와 거래 로그를 표시한다. 종료 결과는 원장 대조, 확인된 문제, 기록 부족 항목을 표시한다.

## 5. 수용 기준
1. 시작 직후 후보가 없어도 운용이 시작되며, 09:05 전까지 토스 후보·현재가 요청을 보내지 않는다.
2. 기업 주식(STOCK)만 선정하며 ETF·ETN·파생상품·유형 미확인·기본정보 조회 실패는 매수하지 않는다. 후보 경계값, 거래량 순서, 정수 주 균등 배분이 원장에서 재현된다.
3. 보유 상태의 5분 일괄 조회, 종목 손익 구간과 보유 0일 때의 세션 한도가 적용된다.
4. 후보와 현재가 호출이 공통 60초 한도를 지킨다. 429 직후 같은 요청을 다시 보내지 않는다.
5. 15시 이후 신규 진입이 없으며 전체 수익률이 0%를 초과하면 전량 청산 후 종료한다. 가격 누락이나 0%·음수에서는 수익 종료하지 않는다. 15:30에는 시세 실패·요청 제한·일시정지 상태에서도 잔량을 전량 청산하거나 마지막 기록가로 가상 정산하고 종료한다.
6. 브라우저 상태 조회는 토스 시세 요청을 만들지 않는다. 거래량 상위 상승 후보·보유·체결 종목명이 없을 때는 캐시를 공유하는 종목 기본정보 조회로 이름을 보강하며, 조회 실패 시에도 상태를 반환한다. 늦게 도착한 응답은 일시정지나 종료 이후 신규 매수를 만들지 않는다.
7. 각 규칙 버전의 원장과 종료 결과를 보존한다. 현재 운영 문서와 다이어그램에서 새 기준을 확인할 수 있다.

## 6. 저장과 접근
`.local/program-trading/toss-paper/`에 가상 거래 기록을 보관한다. 루프백 개발 서버와 동일 출처 변경 요청만 허용한다.
브라우저 고유 키 기반 새 운용은 `.local/program-trading/accounts/<계정 해시>/` 아래에 원장과 보관 세션을 분리한다. 기존 공용 원장은 소유자를 추정해 계정에 붙이지 않는다. 종료 자산은 서비스 전용 DB 테이블에 저장하며, 미저장 종료 상태는 재시도 후 새 세션을 연다.
현재 세션과 보관 세션의 `review.json`을 합쳐 최신 100건까지 보관한다. 한도를 넘으면 오래된 결과 JSON부터 제거하며 원장과 상태 파일은 보관한다. Supabase 복기는 선택 기능이며, 결과와 평가·적용 이벤트는 서버 키로만 저장 및 조회한다. 평가가 매매 규칙을 자동 수정하지 않는다.

## 7. 운영
가상 체결은 비용·슬리피지 가정을 사용한다. 설정과 운용 절차는 [시작 가이드](../program-trading/getting-started.md)에 있다.

## 8. 영향 분석
자동매매 BFF는 로컬 엔진을 직접 호출한다. 앱의 다른 메뉴는 각자의 기존 접근 규칙을 사용한다.
기업 주식 여부는 [토스 공식 종목 기본정보 스펙](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의 securityType으로 판별한다. 최대 100개 후보의 캐시 누락분을 한 번에 조회하며 기존 종목 마스터 캐시를 공유한다.
토스 시세 요청은 호출 그룹별로 재개 시각을 공유한다. 종목 기본정보와 유의사항도 같은 `STOCK` 한도를 쓰며, 단타 워치의 유의사항 목록은 콜드 캐시에서도 간격을 두고 조회한다.

## 9. OPEN QUESTION
계정별 접근과 점수 추세 화면은 여러 사용자가 필요해지면 검토한다. 이번 범위에서는 로컬 운용자가 결과 화면과 CLI로 조회한다.

### 평가에서 개선 적용
완료 세션의 최신 평가에서 개선 적용하기를 누르면 로컬 Codex가 근거를 갖춘 한 가지를 임시 작업 폴더에서 구현한다. 운용 중인 세션이 없고, 허용 범위와 자동매매 검증을 통과하며, 같은 파일에 동시 수정이 없으면 작업 폴더에 반영한다. 결과와 실패 사유를 화면에 표시하고 실제 반영 후에만 이력을 저장한다.

이전 세션 결과는 당시 원장의 규칙 버전을 사용한다.

현재 원장에는 `program-v7-afternoon-close`과 가상 체결가, 순위, 거래량, 정산 사유를 기록한다.
