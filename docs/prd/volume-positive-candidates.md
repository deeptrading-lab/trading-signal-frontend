# 거래량 상위 상승 후보로 단순화

## 1. 문제
기존 프로그램 후보는 수급 순위와 거래량 순위의 합집합으로, 보합·하락 종목도 들어간다. 수급 응답이 비면 거래량 후보도 사용하지 못한다. 사용자는 계좌 수익률 +1%를 목표로 상승 종목에 집중하기를 원한다.

## 2. 사용자
로컬 토스 시세 모의투자를 실행하는 운용자.

## 3. 범위
프로그램 자동매매 후보 로더, 매수 직전 검증, 안내 문구, 규칙 버전, 문서와 모든 생성 다이어그램. AI 단타 메뉴의 별도 추천·매매 로직은 범위 밖이다.

## 4. 동작
1. 기존 한투 실전 거래량 순위(`volume`, 일반주식)의 상위 14개를 먼저 확정한다.
2. 유효한 종목코드·양수 현재가·양수 거래량·유한한 전일 대비율 > 0%인 행만 남긴다. 중복은 첫 행을 유지하며 순위 순서를 보존한다. 하위 순위·수급·지정 종목으로 채우지 않는다.
3. 후보에 `changePercent`와 `previousClose = price / (1 + changePercent / 100)`를 저장한다. 전일 종가는 순위 API의 반올림된 등락률로부터의 추정값이다. 정확한 전일 종가를 독립 조회한 값은 아니다.
4. 시작 시·60초마다 갱신, 120초 만료. 성공했지만 상승 후보가 없으면 `empty`, 미설정·실패는 `unavailable`. 둘 다 신규 매수를 막고 보유 위험 관리는 계속한다.
5. 매수 직전에도 후보 출처가 거래량 단독인지, 조회 당시 상승이었는지, 최신 체결가가 추정 전일 종가를 초과하는지 확인한다. 기존 합집합 스냅샷과 필드 없는 구버전 후보는 거부한다.
6. 돌파 +0.1%, 분 거래량 1.5배, 시세 5초, 스프레드 15bps, 보유 한도·재진입·손절·익절·일일 제한은 유지한다. 후보 탈락 자체는 매도 신호가 아니다.
7. 신규 원장 버전은 `program-v4-volume-positive`. 과거 결과는 보존한다.

## 5. 수용 기준
- 상승 거래량 후보만 순서대로 남고 외국인·기관 API를 호출하지 않는다.
- 보합·하락·비정상 숫자·잘못된 코드·가격·거래량을 제외한다.
- 빈 후보·조회 실패를 구분하고 임의 후보로 대체하지 않는다.
- 유효 후보라도 매수 시점에 보합·하락이면 진입하지 않는다.
- 후보 소실·만료 중에도 보유 손절·청산은 동작한다.
- 타입·관련 테스트·린트와 규칙 생성 및 일치 검사를 통과한다.

## 6. 결과 검토
2026-11-18 09:27~11:02 KST 종료 세션의 로컬 `review.json`과 `trades.jsonl`을 읽었다. 1,000만 원 → 9,795,757원, 비용 후 −204,243원(−2.04243%). 매수·청산 각 9건, 손절 7건 −196,720원, 일일 제한 청산 2건 −7,523원, 익절 0건. 원장 수수료·매도세 합계 38,355원이며 슬리피지는 체결가에 포함된다.

당시 후보·호가·분봉 스냅샷이 없으므로 하락 후보 진입이 손실 원인이었다는 인과관계와 새 기준의 과거 성과를 재현할 수 없다. 이번 변경의 수익 개선은 미검증이다. 향후 별도 거래일에서 비용 후 손익, 손절 비율, 거래 수, 후보 없음 비율을 비교한다.

## 7. 목표 해석
현재 +1%는 계좌 전체 비용 후 세션 평가 목표다. 종목별 익절은 매수가 대비 +2%, 손절 −1%, 종목당 최대 비중 20%다. 한 종목이 +1% 올라도 계좌 기여는 비용 전 최대 약 +0.2%다. 목표 도달 시 즉시 종료하는 로직은 현재 없고 종료 시 평가한다. 이번 후보 변경에서 익절을 +1%로 낮추거나 비중을 높이지 않는다.

짧은 매매는 비용의 영향을 받으므로 비용 후 결과로 검증한다. [SEC 단기매매 안내](https://www.sec.gov/about/reports-publications/investorpubsdaytipshtm)

## 8. 영향 분석
BFF·로컬 엔진 경로 유지. DB·외부 주문·수급 추천 메뉴 변경 없음. 화면 구조·디자인 토큰 변경 없이 카피만 갱신한다. 기존 완료 세션은 재작성하지 않는다. 로컬 서버 재시작 후 새 세션에서 운용한다.
