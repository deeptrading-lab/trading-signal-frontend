# PRD — AI 단타 자동 포트폴리오

## 1. 배경·문제

현재 AI 단타는 사용자가 종목을 고르고 종목마다 투자금·주기·손절을 설정해야 한다. 판단 엔진은 종목별로 안정화됐지만, 사용자가 수급·거래량 후보를 직접 비교하고 여러 세션을 반복 생성해야 해 “오늘 얼마로 단타할지”라는 본래 의도보다 조작 비용이 크다.

## 2. 목표

- 사용자는 **총 투자금 하나만 입력**한다.
- 시스템은 당일 외국인·기관 수급 상위와 거래량 상위를 합쳐 3~5종목을 자동 선정한다.
- 총액을 종목별로 배분하고 기존 AI 단타 세션을 한 번에 시작한다.
- 종목별 체결은 독립적으로 안전하게 수행하되, 화면은 합산 투자금·평가금·수익률로 보여준다.
- 실제 주문이 아닌 모의매매이며 15:40 KST 자동 종료 원칙을 유지한다.

## 3. 비목표

- 실계좌 주문, 증권사 주문 API 연결, 공매도, 오버나이트 보유.
- 포트폴리오 종목 간 자금을 장중 실시간 이전하는 리밸런싱.
- 수익 보장 또는 추천 종목의 투자 적합성 주장.
- 기존 수동 종목 워치·단일 종목 모의매매 제거.

## 4. 사용자 흐름

1. 사용자가 `AI 단타` 메뉴에 진입한다.
2. 기본값 1,000만원인 투자금을 확인하거나 수정한다.
3. `자동 모의매매 시작`을 누른다.
4. 시스템이 현재 후보를 점수화해 포트폴리오를 만들고 종목별 첫 AI 판단을 순차 실행한다.
5. 화면에서 합산 평가금·수익률과 종목별 배정 비중을 확인한다.
6. 이후 기존 5분 자동 틱과 60초 리스크 스윕이 종목별로 사고팔며, 15:40에 모두 종료한다.

## 5. 기능 요구사항·수용 기준

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| AC-1 | 단일 입력 | 자동 영역의 필수 사용자 입력은 총 투자금 하나뿐이다. |
| AC-2 | 후보 합성 | 외국인·기관 수급 Top과 거래량 Top을 ticker로 합치며 양쪽 중복 종목을 우대한다. |
| AC-3 | 분산 수 | 100만~1,000만원 미만은 3종목, 1,000만~3,000만원 미만은 4종목, 3,000만원 이상은 최대 5종목이다. 후보 부족 시 가능한 수만 사용하되 최소 2종목이어야 한다. |
| AC-4 | 현금 버퍼 | 총액의 10%를 미배정 현금으로 남기고 나머지를 후보 점수에 비례해 1만원 단위로 배정한다. |
| AC-5 | 결정성 | 동일 후보·동일 금액이면 동일 종목·배정 결과가 나온다. |
| AC-6 | 기존 엔진 재사용 | 각 종목은 `cli-agent`, 균형 위험, 5분 판단, 포지션 −5%, 세션 −7% 하드스톱으로 생성한다. |
| AC-7 | 묶음 식별 | 종목별 세션에 같은 `portfolioId`, 이름, 배정 비중을 저장한다. |
| AC-8 | 합산 현황 | 최신 자동 포트폴리오의 종목 수, 시작 투자금, 평가금, 합산 수익률, 종목별 비중을 표시한다. |
| AC-9 | 중복 방지 | 오늘 이미 단타 세션이 있는 종목은 새 자동 후보에서 제외한다. |
| AC-10 | 실패 안전 | 후보 부족·최소 금액 미달·CLI 실패는 한글 인라인 오류로 알리며 실제 주문은 발생하지 않는다. |

## 6. 선정·배분 정책

- 수급 점수: `1.15 × (12 - 수급 순위)`.
- 거래량 점수: `12 - 거래량 순위`.
- 두 목록 중복 보너스: `+5`.
- 점수 내림차순, 동점은 ticker 오름차순으로 선정한다.
- 종목별 세션 예산은 `(총액 × 종목 점수 / 선택 종목 점수 합)`을 1만원 단위 내림하고 잔액은 1위 종목에 더한다. 각 세션의 기존 10% 현금 버퍼가 동일하게 적용되어 합산 현금도 총액의 10%가 된다.
- 이 정책은 설명 가능하고 결정론적인 MVP 규칙이다. 축적된 틱 라벨로 승률이 확인되기 전에는 AI가 후보 자체를 자유 생성하지 않는다.

## 7. 운영·측정

- 핵심 지표: 자동 포트폴리오 시작 수, 시작 성공 종목 수, 종목별 왕복 횟수, 합산 일 수익률, 최대 낙폭, 기존 무선별 진입 베이스라인 대비 conviction 버킷 승률.
- 운영 원칙: 로컬 CLI 전용, Vercel에서는 기존 관리자 게이트 유지, 실제 매매 미지원.
- 부분 실패 시 이미 생성된 세션은 보존하고 화면에 표시한다. 재시도 시 오늘 세션 종목은 후보에서 제외한다.

## 8. 영향 분석

- UI: `/intraday` 최상단에 자동 포트폴리오 영역 추가. 기존 검색·추천·워치 표는 고급/수동 흐름으로 유지.
- API/BFF: 기존 `/api/paper-trading/sessions` 요청에 optional 포트폴리오 메타데이터만 추가한다.
- 엔진: 종목별 `intradayCli`, 가상체결, 스케줄러는 변경하지 않는다.
- 데이터: 세션 payload JSON에 optional 필드가 추가되어 DB migration이 필요 없다.
- 보안: 브라우저는 기존 same-origin axios 경로만 사용하고 CLI·시세 키는 서버에 남는다.

## 9. OPEN QUESTION

1. 장중 종목 간 자금 재배분을 할 것인가? **PM 권고: MVP는 하지 않는다.** 독립 세션 손익 데이터가 쌓인 뒤 일 단위 리밸런싱부터 검토한다.
2. 수급과 거래량 가중치를 개인화할 것인가? **PM 권고: 고정값으로 시작한다.** 사용자 입력을 늘리지 않고 라벨 실측으로 조정한다.
3. 후보 경고 종목을 전부 제외할 것인가? **PM 권고: 기존 deterministic warning gate를 최종 안전장치로 유지한다.** 후보 단계에서 이중 차단하면 후보 부족과 선택 편향이 커진다.
