# 프로그램 자동매매 전용 메뉴

> 이전 화면 기록. 현재 범위는 [로컬 토스 모의매매 PRD](../prd/local-program-trading.md)에 있다.

2026-11-01 실거래 후속 스펙: [stock-order-integration.md](stock-order-integration.md). 아래 최초 구현의 합성 전용 제한은 후속 스펙으로 대체한다.

> 이 문서는 1차 메뉴·리플레이 범위다. 후속 실계좌 실행의 최신 계약은 [실계좌 실행 PRD](stock-order-integration.md)를 따른다. 아래의 실주문 미구현 표기는 1차 산출물 당시 경계이며 후속 구현 검증은 별도 실계좌 QA에서 추적한다.

## 1. 문제
AI 단타 가이드와 프로그램 운용을 분리하고 계좌 연결부터 시작·종료·결과 확인까지 짧은 흐름을 제공한다. 운용 결과는 계속 보존하여 종료 후 복기에 사용한다.

## 2. 사용자와 목표
한국투자증권 계좌를 사용하는 개인 운용자. 연결 후 시작 한 번, 종료 한 번으로 운용하고 거래 전후 잔액과 비용 후 수익률을 확인한다.

## 3. 범위와 구현 경계
- 독립 `/program-trading` 메뉴. AI 단타 가이드와 기존 기능은 유지한다.
- 화면에는 요약 다이어그램, 상세 다이어그램, 한투 계정 연동, 시작·종료, 수익률 현황, 거래 로그만 둔다.
- 현재 엔진은 합성 시세·가상 1천만원·즉시 전량체결 리플레이다. 계좌 연결 성공과 실제 주문 가능 상태를 분리한다. 실계좌 시세·주문·체결대사가 준비되지 않은 상태를 실거래 완료로 표현하지 않는다.
- 계정 비밀은 브라우저 영구 저장소·거래 로그·복기 파일에 남기지 않는다. BFF를 경유하고 인증 오류에 민감한 원문을 노출하지 않는다.
- 계좌번호 8자리·상품코드 2자리, 모의/실전 구분, Open API 키를 입력한다. 한투 토큰·잔액 조회 성공 후 `.env.local`에 `PROGRAM_KIS_*`로 저장하며 파일 권한은 0600으로 제한한다. 기존 시세 조회용 KIS 계정은 교체하지 않는다. 화면에는 마스킹 번호·연결시각·실제 조회잔액을 가상 운용 지표와 구분해 표시한다.

## 4. 동작과 정책
- 후보: AI 단타 가이드의 동일 공급자에서 거래량 상위 10개, 외국인 순매수 상위 10개, 기관 순매수 상위 10개를 받아 중복 제거. 불가/만료 시 신규 매수 중지, 보유 위험관리 유지.
- 시작: 엔진 준비 상태 검증 후 시작 전 잔액, 목표 수익률, 규칙 버전, 시작 시각을 기록한다. 현재 리플레이 목표 기본값은 비용 후 1%이며 엔진 상수로 문서·다이어그램과 동기화한다. 계정 연결은 실제 잔액 조회용이고 가상 운용 시작과 독립이다. 실제 잔액을 가상 운용의 시작금액·정산금액으로 섞지 않는다. 최종 실계좌 운용은 연결 계좌·시세·주문·대사 준비를 모두 검증해야 시작할 수 있다.
- 종료: 신규매수 차단→보유분 청산 재시도→잔존 보유가 없을 때 완료. 실주문 연동시 미체결 취소·체결/잔고대사까지 완료해야 종료로 인정한다. 시세 불능 시 청산 완료로 처리하지 않는다.
- 정산: 완료 시점에 전 잔액·후 잔액·손익·비용 후 수익률을 확정한다. 진행중에는 평가 수익률로 표시한다. 시작 전 미확정 지표는 대시로 표시한다. 가상 매매 전후 자산은 계좌 조회잔액과 혼합하지 않는다. 실계좌의 입출금은 손익과 분리해야 한다.
- 원장: 별도 JSONL 파일에 누적한다. 화면용 최근 로그 제한과 독립적이며 재시작으로 과거 거래가 사라지지 않는다. 로그 쓰기 실패 시 신규 주문을 차단한다.
- 복기: 종료 후 전체 원장을 근거로 거래별 진입/청산 사유·비용·손익을 요약한다. 목표 이상 달성시 `규칙 유지`, 미달시 검토 가이드만 생성한다. 코드/매매 파라미터 자동 변경은 없다.

## 6. 운영과 검증
`npm run program:dev` 한 명령으로 웹과 워커를 함께 실행한다. 로컬 독립 워커를 유지한다. Next/Vercel 요청 수명에 지속 매매 루프를 얹지 않는다. 단일 일자 리플레이 완료 세션은 재시작할 수 없다. 새 실험은 워커 종료 후 `.local/program-trading` 전체를 별도 보관하고 새 워커를 시작한다. 실제 계좌 주문은 별도 검증 없이 실행하지 않는다. 엔진·원장·목표판정 테스트, 타입검사, 다이어그램 생성 일치 검사를 수행한다. 브라우저에서 모바일·데스크톱, 네트워크 오류, 로그 영역 접근성을 확인한다.

## 7. 위험과 출시 한계
현재 합성 체결 결과는 실계좌 수익이 아니다. 실계좌 운용을 제공하려면 실시간 시세, 주문 멱등성, 부분체결/거절/취소, 재시작 대사, 실제 거래일·KST 시계, 상시 실행 환경이 모두 필요하다. 이 경계를 최종 전달에서 명시한다.

## 8. 영향 분석
메뉴·가이드 패널 분리, 기존 프로그램 워커/BFF/훅 확장, JSONL와 복기 파일, HTML 생성기/템플릿에 영향. DB·AI 단타 판단 프롬프트 변경은 없다. 기존 후보 공급자를 재사용한다.

## 9. OPEN QUESTION
- 실계좌 주문을 이번 작업에서 완성할 수 있는가? 권고: 기존 리플레이와 계정조회는 구분하여 제공하고 주문·체결대사·시세가 빠진 실거래 시작은 차단한다. 미완성 범위는 완료로 보고하지 않는다.
- 목표치 변경 UX는 필요한가? 권고: 이번 최소 화면에서는 문서화한 기본 목표를 사용하고 시작 시 원장에 고정한다. 실제 계좌 적용 전 운용자가 목표·손실한도를 결정해야 한다.

## 다이어그램 도구 적용 (2026-11-02)
사용자 요청에 따라 Archify를 설치하고 요약·상세 생성에 적용한다. 수용 기준은 기존 조건·우선순위·리플레이 구분 보존, 한국어 뷰어, 화면 확대·노드 포커스, 재생성/일치 검사 성공이다. 영향 범위는 생성 스크립트·생성 HTML/JSON·iframe/CSP이며, 주문 엔진 변경은 없다. 설치는 생성 환경에만 필요하고 앱 런타임에는 필요하지 않다.

## 다이어그램 모달 전환 (2026-11-02)
사용자 요청에 따라 본문 다이어그램을 제거하고 상단 `매매 기준 보기` 버튼으로 연다. 요약/상세 전환·크게 보기/인쇄는 모달 안에서 제공한다. 데스크톱은 중앙 모달, 모바일은 전체 화면이다. 닫기 버튼·배경 클릭·Esc로 닫고 버튼으로 포커스를 복원한다. 닫힌 동안 iframe을 마운트하지 않으며 계좌·운용·로그만 기본 화면에 노출한다.

## UI/UX 플로우차트 개선 (2026-11-02)
- 사용자 요청: 디자이너 관점에서 차트를 재검토하고 개선한다.
- 문제: 좌우 지그재그 읽기, 반복된 ‘계속’ 제목, 설명문에 묻힌 실패 분기, 하나로 길게 연결된 매수·매도·정산.
- 범위: 모달 안에서 전체 흐름/매수 조건/매도 우선순위/종료·정산을 선택한다. 각 상세 차트는 위→아래로 읽으며 충족·미충족, 해당·해당 없음, 목표 달성·미달을 별도 경로로 표시한다.
- 수용 기준: 매수는 모든 조건 충족 경로만 주문으로 연결, 매도는 상위 조건 해당 시 그 결과에서 종료, 정산 미충족은 수익률 확정으로 연결하지 않음. 시각 검수·모바일 선택/닫기·재생성 일치 검사를 통과한다.
- 엔진·매매 수치 변경 없음. 기존 detail URL은 매수 조건 보기의 호환 별칭으로 제공한다. 주요 미충족 동작과 매도 우선순위를 위상 테스트로 보호한다.
