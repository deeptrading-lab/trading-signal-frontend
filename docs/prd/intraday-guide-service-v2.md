# PRD — AI 단타 가이드 서비스 v2

## 1. 배경·문제

기존 AI 단타 가이드는 이용권 진입, 최신 매수·매도 알림, 수행/패스 원장을 제공한다. 그러나 고객 입장에서는 가이드가 없을 때 시스템이 멈춘 것인지, 종목을 분석 중인지 알기 어렵고, `+2% 목표 / -1% 손절` 전략이 자신의 기준 금액에서 얼마의 기대이익·손실로 이어지는지도 시작 전에 확인하기 어렵다. 또한 오래된 가격의 가이드를 뒤늦게 수행할 수 있어 실제 시장가와 추천 조건이 어긋날 수 있다.

대고객 서비스로 전환하기 전에는 수익률을 강조하기보다 전략의 작동 조건, 가이드 유효성, 운영 상태, 원금손실 가능성을 같은 위계에서 설명해야 한다.

## 2. 목표

- 시작 전에 종목 목표 `+2%`, 손절 `-1%`, 최대 투입 `50%`, 최대 3종목이라는 전략 구조를 이해시킨다.
- 입력한 기준 금액으로 1회전 비용 전 목표이익과 계획손실을 계산해 보여준다.
- 원금손실과 실제 주문 책임을 확인한 사용자만 가이드 런을 시작할 수 있고, 확인 시각을 런에 남긴다.
- 진행 중에는 사용 슬롯, 빈 슬롯, 최근 스크리닝 결과와 후보 대기 이유를 설명한다.
- 가이드마다 유효 종료시각, 목표/손절 금액, 최대 기대이익·계획손실, 핵심 위험을 보여준다.
- 생성 후 10분이 지난 가이드는 화면과 서버 양쪽에서 수행 처리하지 않는다.

## 3. 범위와 사용자 흐름

### 3.1 시작 전

1. 사용자는 기준 금액을 입력한다.
2. 화면은 기준 금액의 최대 50%가 분산 투입된다는 가정으로 비용 전 목표이익 `기준 금액 × 1%`, 계획손실 `기준 금액 × 0.5%`를 표시한다.
3. 사용자는 `원금손실 가능성과 실제 주문 책임을 확인했어요`를 체크한다.
4. 체크 전에는 시작 CTA가 비활성화된다.
5. 시작 요청은 `riskAcknowledgedAt`을 포함하고 서버가 guide 목적 요청에 한해 유효한 시각인지 검사한다.

### 3.2 후보 분석 중

1. 상태 스트립에 활성 분석 종목 수, 빈 슬롯 수, 최근 후보 통과 수를 표시한다.
2. 행동 가이드가 없으면 마지막 스크리너 결과와 최근 skip 사유를 사용해 `조건을 충족한 후보 대기`, `실시간 랭킹 연결 대기`, `쿨다운·중복 제외` 등으로 설명한다.
3. 빈 슬롯을 억지로 채우지 않는 것이 품질 정책임을 안내한다.

### 3.3 행동 가이드

1. 가이드 생성 시각부터 10분을 유효시간으로 사용한다.
2. 유효한 가이드에는 `HH:mm까지 확인`을 표시한다.
3. 매수 가이드에는 기준가·수량·예상금액과 함께 목표가, 손절가, 비용 전 기대이익, 계획손실을 표시한다.
4. AI 판단의 핵심 위험 메모는 최대 2개만 노출한다.
5. 만료된 가이드는 행동 CTA에서 제외하고 기록에 `기한 만료`로 남긴다.
6. 서버는 만료된 guideId의 `performed`와 `passed` 요청을 모두 `409`로 거절한다.

## 4. 데이터·상태 모델

- `AutopilotRun.riskAcknowledgedAt?: string`: guide 시작 전 원금손실·주문 책임 확인 시각. 레거시 런은 optional로 호환한다.
- `StartAutopilotRunRequest.riskAcknowledgedAt?: string`: research 런에는 요구하지 않는다.
- `IntradayGuideItem.validUntil`: 원본 tick 생성시각 + 10분.
- `IntradayGuideItem.status`: `pending | performed | passed | expired`.
- `convictionScore`, `riskNotes`: 원본 tick decision에서 읽는 표시 전용 스냅샷이며 AI 원본을 수정하지 않는다.
- 만료 판정의 서버 진실 원천은 원본 tick `createdAt`이다. 클라이언트가 보낸 만료시각을 신뢰하지 않는다.

## 5. 기능 요구사항·수용 기준

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| AC-1 | 전략 사전 설명 | 시작 전에 +2%/-1%/최대 50%/최대 3종목을 한 화면에서 확인한다. |
| AC-2 | 금액 환산 | 1,000만 원 입력 시 비용 전 목표 `+100,000원`, 계획손실 `-50,000원`을 표시한다. |
| AC-3 | 위험 확인 | guide 시작은 유효한 `riskAcknowledgedAt` 없이는 422이며 UI CTA도 비활성이다. |
| AC-4 | 운영 투명성 | 진행 중 활성 슬롯·빈 슬롯·최근 스크리너 통과 수가 보인다. |
| AC-5 | 대기 설명 | 가이드가 없을 때 멈춤으로 오인하지 않도록 최근 분석 결과 또는 대기 사유를 표시한다. |
| AC-6 | 가이드 계획 | 매수 가이드에서 목표가·손절가·기대이익·계획손실과 위험 메모를 확인한다. |
| AC-7 | 유효시간 | 10분 전 가이드는 pending, 10분 이상 지난 미응답은 expired다. |
| AC-8 | 서버 만료 방어 | 만료된 가이드 응답은 409이며 원장에 기록되지 않는다. |
| AC-9 | 레거시 호환 | 과거 런·응답은 새 optional 필드 없이도 조회된다. |
| AC-10 | 한글·접근성 | 체크박스와 상태 영역에 접근 가능한 이름이 있고 ticker 외 문구는 한글이다. |
| AC-11 | 오인 방지 | 비용·세금·슬리피지 미포함, 실제 주문 아님, 수익 비보장을 시작 전과 진행 중에 명시한다. |
| AC-12 | 반응형 | 390px에서는 전략·금액 카드가 2열 이하, 1280px에서는 4열로 표시되고 CTA가 잘리지 않는다. |

## 6. 비목표

- 실제 결제, 증권사 주문, 체결 확인 또는 사용자 계좌 연동.
- 개인의 재산·경험·투자성향에 맞춘 1:1 자문.
- `+2%/-1%` 전략의 수익 보장 또는 일일 목표 강제 달성.
- 추천가와 다른 실제 체결가·수량 입력. 이 기능은 사용자 원장과 매도 기준의 동기화 설계 후 별도 도입한다.
- 법률 검토·신고·등록을 UI 문구만으로 대체하는 것.

## 7. 측정·운영

- 위험 확인 노출 대비 시작 전환율과 이탈률.
- 후보 대기 상태에서의 페이지 이탈률 및 `직접 분석 도구` 전환율.
- 가이드 생성→응답까지 중앙값, 만료율, 수행률, 패스율.
- 추천 시각 대비 응답 지연과 이후 수익률의 관계.
- 비용 후 승률과 손익비. 왕복 비용을 0.28%로 가정하면 +2%/-1% 구조의 단순 손익분기 승률은 약 42.7%이며, 이 값은 상품 약속이 아니라 운영 중단·재검토 기준으로만 사용한다.

## 8. 영향 분석

- UI: `IntradayAutopilotCard` 시작 카드, 진행 상태, 행동 카드, 활동 상태를 확장한다.
- 도메인: `guideProduct.ts`에 금액 환산과 운영 상태 설명을 순수 함수로 둔다.
- 피드: 가이드 유효시간·만료·판단 위험 메타를 파생한다.
- API/BFF: guide 시작의 위험 확인 시각을 검증하고 만료 응답을 409로 변환한다.
- 서버: 런 payload JSON에 optional 확인 시각만 추가하며 DB 마이그레이션은 없다.
- 보안: 만료 판정과 원본 가격·수량 검증은 서버에서 수행한다.
- 법무: 유료 공개 전 유사투자자문업 해당 여부, 단방향/양방향 제공 방식, 표시·광고 문구를 별도 검토해야 한다.

## 9. OPEN QUESTION

1. 실제 체결가·부분체결을 입력받을 것인가? **PM 권고: 이번 버전에서는 받지 않는다.** 실제값을 받으면 고객별 +2% 매도 기준까지 같은 원장으로 재설계해야 하며, 입력만 먼저 받으면 더 위험하다.
2. 가이드 유효시간은 몇 분인가? **PM 권고: 10분.** 5분 판단 주기 두 번 안에 응답할 수 있게 하되 가격 괴리가 커지는 장기 대기는 막는다.
3. 위험 확인을 매일 받을 것인가? **PM 권고: 런마다 받는다.** 오늘 이용권 단위와 맞고 확인 시각을 감사 가능하게 남길 수 있다.
4. 9,900원 가격을 유지할 것인가? **PM 권고: PG·법률 검토 전에는 `체험` 상태를 유지하고 가격 실험은 전환 데이터에 포함하지 않는다.**

## 10. 3차 검토와 반영

### 1차 — 전략·수익구조 검토

- 발견: `일 1%`를 상품 약속처럼 앞세우면 빈 슬롯을 억지로 채우거나 과열 종목을 추격할 유인이 생긴다. 비용 후 손익분기 승률도 50%가 아니라 약 42.7%이므로 표본 기반 검증이 선행되어야 한다.
- 반영: `종목 +2%`와 `포트폴리오 비용 전 +1% 시나리오`를 구분하고, 빈 슬롯은 품질 정책으로 설명한다. 수익률은 보장 문구가 아닌 시나리오로만 표시한다.

### 2차 — 소비자보호·운영위험 검토

- 발견: 종목·가격·수량·시점을 유료로 제공하는 서비스는 단순 면책 문구만으로 공개 운영할 수 있다고 단정할 수 없다. 2024년 8월 시행된 규율은 유사투자자문업자의 단방향·불특정 다수 조언, 원금손실 고지, 이익보장 금지 등을 명시한다.
- 반영: 현 단계는 결제 미연동 체험으로 제한하고, 시작마다 원금손실·주문 책임 확인을 받는다. 유료 공개 전 등록·신고 및 제공 채널에 대한 별도 법률 검토를 출시 게이트로 둔다.

### 3차 — 고객 UX·오류회복 검토

- 발견: 고객은 `HOLD`를 멈춤으로 오인하고, 지난 가격의 알림을 유효한 주문 지시로 오인할 수 있다. 모든 분석 정보를 펼치면 현재 행동도 묻힌다.
- 반영: 운영 상태에는 `분석 중/빈 슬롯/최근 후보`만 압축하고, 행동 카드에는 10분 유효시간과 손익 계획·위험 2개만 보여준다. 만료는 UI 표시만이 아니라 서버에서 거절한다.
