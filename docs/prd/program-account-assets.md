# 계정별 자동매매 자산

## 1. 문제
모의매매 시작 자산이 매번 1,000만 원으로 초기화되어 이전 결과를 이어서 운용할 수 없다.
## 2. 사용자
브라우저 고유 키으로 로컬 자동매매를 운용하는 사용자.
## 3. 범위
계정별 자산 DB 조회·종료 자산 저장·수동 자산 설정 화면. 실거래 계좌 잔고와는 별개인 모의 자산이다.
## 4. 동작
- 로컬 자동매매는 Google 로그인 없이 사용한다. 첫 페이지 요청에서 256비트 무작위 키를 HttpOnly·SameSite=Lax 지속 쿠키에 발급하고 365일 만료를 방문 때 갱신한다. 페이지·자산·복기에서 같은 키를 재사용한다. DB와 원장에는 원본 키 대신 해시만 사용한다.
- 브라우저/주소 변경 또는 쿠키 삭제 시 새 기록으로 시작한다. 배포 환경의 Google 로그인은 변경하지 않는다.
- 새 세션 시작 시 DB의 가장 최근 종료 자산 또는 수동 저장값을 읽는다. 행이 없는 경우에만 1,000만 원을 사용한다. 0원은 저장값이며 시작은 차단한다. DB 오류 시 시작하지 않는다.
- 기존 세션 재개 시 시작 자산을 다시 변경하지 않는다. 계정별 런타임과 로컬 원장 경로를 분리한다.
- 종료 후 최종 자산을 DB에 저장한다. 동일 종료 세션의 재시도는 중복 저장하지 않는다. 저장 실패는 종료를 취소하지 않고 오류 표시·30초 간격 재시도로 복구한다. 미저장 종료 세션은 새 세션으로 넘기지 않는다.
- `/program-trading/assets`에서 저장값·출처·시각을 보고 원 단위 정수 금액을 저장한다. 운용/일시정지/청산 중에는 변경을 차단하고 종료 후에 변경한다.
## 5. 수용 기준
계정 간 조회·저장·원장을 격리한다. 브라우저 키 누락·형식 오류는 거부한다. 기본값/저장값/0원/DB 실패/수동 저장/자동 종료/중복 재시도/과거 종료의 지연 저장을 검증한다.
## 6. 화면
운용 손익 헤더의 목표 수익률 옆에 테두리 없는 아이콘+텍스트 자산 설정 링크와 종료 자산 저장 상태 및 재시도 버튼을 제공한다. 자산 설정 화면은 모바일 1열·lg 이상 자산 요약과 변경 폼 2열, sm 이상 동일 높이의 입력과 저장 버튼 병렬, 한글 레이블과 inline 오류·저장 성공 상태를 제공한다.
## 7. 운영
기존 공유 원장은 소유자를 추정하지 않고 그대로 보존한다. 새 계정 세션부터 계정별 경로를 사용한다. 서버 전용 키만 DB에 접근하며 요청 본문이나 URL에서 소유 식별자를 받지 않고 지속 쿠키의 해시로만 구분한다.
## 8. 영향 분석
브라우저 지속 쿠키, 자동매매 런타임·로그 다운로드·로컬 복기 경로, BFF·도메인 훅·query key, 서비스 전용 자산 이벤트 테이블을 연결한다. 신규 토큰 없이 기존 디자인을 재사용한다.
## 9. OPEN QUESTION
사용자 확정: 브라우저 고유 키 기준으로 저장하고, 직전 종료 자산 또는 최근 수동 저장값을 다음 시작 금액으로 사용한다.
