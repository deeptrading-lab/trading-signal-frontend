# 프로그램 자동매매 실계좌 실행

## 1. 문제
계좌조회와 합성 리플레이만으로는 계좌 연결 후 실제 자동매매를 시작하고 종료하는 사용자 목표를 충족하지 못한다. 주문 접수와 체결을 분리하여 실제 한투 계좌 운용을 제공한다.

## 2. 사용자와 목표
한국투자증권 Open API 계좌를 연결한 운용자. 계좌 입력 후 시작·종료 두 조작으로 운용하며 실제 잔액·거래상태·완료 수익률을 확인한다.

## 3. 범위와 기존 지침 적용
- 주문 어댑터는 서버 전용 `lib/server/programTrading/`에 둔다. 기존 `lib/api/kis/`의 조회 전용 계약은 유지한다.
- 기존 `lib/api/kis/README.md`, `index.ts`, `client.ts`의 주문 미구현·매주문 비밀번호 권고는 당시 조회 전용 PR의 범위다. 이번 사용자의 계좌 연결 후 자동 실행 요청에 따라 이 PRD의 세션 단위 시작·주문한도·영속감사·확정대사 정책으로 대체한다. 매주문 비밀번호 입력을 추가하지 않는다.
- 화면은 요약·상세 도표/계좌/시작/종료/수익률/로그의 7요소를 유지한다. 시작 버튼은 실전·한투 모의·리플레이의 실행 대상을 문구로 명확히 알린다.
- 연결한 환경을 고정한다: `vts`는 한투 모의투자 서버, `prod`는 실계좌 주문 서버. 합성 `replay`는 별도 모드이며 실제 성과에 섞지 않는다.
- 구현 검증은 fake broker로 수행한다. 개발/QA 과정에서 실제 주문을 보내지 않는다. 자동 시작은 없고 사용자 시작 명령만 주문 세션을 연다.

## 4. 동작 정책
### 시작과 실행
- 계좌/환경·토큰·잔액·거래일·한국 장중 시각·후보 신선도·주문 가능 상태를 검증한다. 조회 실패를 영업일 또는 주문가능으로 간주하지 않는다.
- 시작 전 계좌의 기존 보유 및 미체결 주문이 있으면 거부한다. 모든 조회 페이지를 확인하여 외부 보유분을 자동 청산하지 않는다.
- 시작 시 계좌 식별 해시, 환경, 거래일, 전 자산·현금, 목표 수익률 1%, 규칙 버전, 시각을 기록한다. 비밀키는 `.env.local`에만 보관한다.
- 후보는 거래량10·외국인순매수10·기관순매수10 합집합. 시세·호가·직전 3분 고가·거래량 배율·타임스탬프를 실제 한투 조회로 확인한다. 현재 진행분 봉은 기준 3분 고가에서 제외한다. 보유분을 먼저 조회하고 신규 후보는 틱마다 1개씩 순환 조회하여 호출 지연을 제한한다. 시세 수신 후 경과시간까지 포함하여 5초 초과 데이터는 사용하지 않는다.
- 매수는 현재 확인한 가격의 지정가, 매도는 시장가다. 매수 1회 원금 상한 기본 100만원(`KIS_ORDER_MAX_KRW`로 변경)을 서버에서 검사한다. 매도 가격은 보장하지 않는다.
- 주문 전 신호·수량·가격·사유·한도를 영속 의도로 저장하고 fsync 후 한 번 전송한다. 저장 실패시 전송하지 않는다. 매수금액 상한과 미수 없는 현금 가능수량·총위험 예산을 서버에서 검사한다.
- 성공 응답은 접수이며 체결이 아니다. 주문번호로 누적 체결량을 조회하고 이전 누적량과 차분만 원장에 추가한다. 부분체결·거절·취소를 구분한다.
- 명시적으로 거절된 주문은 rejected로 기록하고 자동매수를 중지하며 10분 재진입 대기를 적용한다. 시간초과 또는 응답을 확정할 수 없는 주문은 unknown으로 잠그고 재전송하지 않는다. 시작·추가매수·같은 잔량에 대한 청산 주문도 중복하지 않는다. 주문내역·잔고 대사로 원주문 식별 전 운용 재개 금지.
- 원주문 번호를 확인한 운용자는 워커 종료 후 `npm run program:resolve -- --client-id=<의도ID> --broker-order-id=<확인주문번호> --date=YYYYMMDD --confirm-broker-order=yes`로 해당 의도에 연결할 수 있다. 동일 포트 잠금·전체조회·일자·종목·방향·수량·중복연결 검증 후 WAL만 기록하며 주문·취소는 하지 않는다. 워커 재시작 대사가 필요하다.
- 복구용 버튼은 추가하지 않는다. 확정된 주문·잔고 대사가 완료된 상태에서 기존 시작 명령을 수동 재개로 사용한다. unknown이 남으면 시작을 거절하며 모호한 매칭으로 잠금을 해제하지 않는다.
- 재시작시 자동매수 재개하지 않는다. 영속 미확정 의도와 미체결·잔고를 대사하고 운용자가 수동 재개한다. 운용중·종료중·대사필요 상태에서 계좌/환경 변경을 차단한다.

### 종료와 정산
- 종료 명령은 신규매수 차단 → 미체결 취소 → 취소/체결 최종 상태 확인 → 이 세션 실제 보유 잔량만 매도 → 체결·잔고 재대사 순서다. 취소 접수 자체를 취소 완료로 보지 않는다.
- 취소 도중 추가 체결되면 최신 누적체결량을 반영하여 청산수량을 다시 산정한다. 미확정 주문·남은 보유·잔고 불일치가 있으면 완료로 표기하지 않는다.
- 잔여 보유·미체결 수량 및 마지막 계좌 대사시각은 거래 로그 내부에 표시한다. 설정 패널을 추가하지 않는다.
- 시세 단절/장 종료/거래정지로 청산하지 못하면 보유·미체결 수량과 종료대기 사유를 표시한다. 체결을 가정해 잔액을 만들지 않는다.
- 완료 시 실제 계좌 총평가자산 전후 차이와 비용 반영 수익률을 확정한다. 당일 실제 거래비용(`thdt_tlex_amt`)의 시작 기준값과 일자별 차액을 반영하여 거래대금과 잔액 증감을 대사한다. 비용 미조회 또는 1원 초과 불일치이면 정산·목표판정을 보류한다. 계좌 입출금/외부거래가 감지되면 순수 전략수익으로 단정하지 않고 대사 필요를 표시한다.
- 목표 달성시 규칙 유지와 개선제안 생략. 목표 미달시 전체 원장 근거의 검토 가이드만 생성한다. 자동 코드/파라미터 변경은 없다.

## 6. 운영과 검증
로컬 상시 Node 워커와 Next BFF를 유지한다. `npm run program:dev`로 실행한다. 브라우저 종료와 무관하게 운용하되 워커 종료시 자동 재개는 없다. 실제 네트워크 주문 없는 fake broker 테스트로 정상체결·부분체결·거절·중복조회·timeout·취소경합·파일실패·재시작·장외·잔고불일치를 검증한다.

## 7. 위험과 한계
HTTP 결과 불명확은 체결 실패를 뜻하지 않는다. 원주문 확인 전 재송신 금지 정책을 유지한다. 실제 증권사 모의/실전 계약 차이와 장시간 운용은 실제 연결 검증 전 별도 검증 대상으로 기록한다. 구현과 실제 계좌 검증의 완료 여부를 분리 보고한다.

## 8. 영향 분석
프로그램 전용 broker/실시세 공급/영속 execution engine/worker/BFF/계좌 변경 제어·UI모드·주문 로그·HTML 생성기에 영향. 기존 조회용 KIS 모듈, AI단타 가이드 판단, DB는 변경하지 않는다.
