# PRD — intraday-stop-slippage (단타 손절 신뢰성 A+B+C)

- 작성: 2026-07-09 · 갱신: 2026-07-09 (A+B+C 확정)
- 상태: **구현 확정** (§7 결정 완료)
- 브랜치: `feature/intraday-stop-slippage`
- 맥락: [intraday-decision-overhaul](intraday-decision-overhaul.md) — conviction judge 첫 실전(7/9) 데이터

## 1. 배경 / 문제

7/9 첫 실전 체결 8건 중 **다스코**: 진입 5,473 · 손절선 **5,420(−1%)** · 실제 청산 **5,077(−7.96%)**.
12:00봉 장대음봉이 손절선을 건너뛰고 급락 → 다음 5분 틱(12:05)에서야 청산. **손절선의 8배 손실.**

원인은 손절 판정·체결이 **틱 주기(5분)에 묶여** 틱 사이 급락을 감지·차단 못 하기 때문.

**"버텼으면 됐다"가 아니다 — 데이터 검증**: 오늘 손절 6건 중 청산 후 진입가 회복 **2건뿐, 4건 미회복**
(다스코도 청산 후 최저 −10.7%까지 더 빠지고 최고여도 −1.5%로 본전 미달). 즉 "홀드/물타기"는 표본상
지는 전략이었고, 진짜 개선은 **손절을 제대로(일찍) 작동**시키는 것. 다스코를 −1%(5,420)에서 끊었으면
드라마 자체가 없었다.

## 2. 근본 원인 (코드)

- **판정 주기 = 틱 주기**: `resolveForcedExit`(`lib/server/paperTrading/virtualExecution.ts:213`)는 틱마다
  1회, 그 틱 스냅샷 가격 1개(`price.price`, 5분에 1회 갱신·`MAX_STALE_PRICE_SECONDS=180`)로만
  `last <= stopPrice` 검사. 틱 사이 급락 미감지.
- **체결가 = 감지 시점 시장가**: 트리거 시 스톱 레벨이 아닌 감지 틱 현재가로 청산(갭 하락분 전부 실현).
- **하드스톱 백스톱 부재**: `PAPER_TRADING_POSITION_HARD_STOP_PCT=-5`·`SESSION_HARD_STOP_PCT=-7` 은
  **mock 전용**(`decisionProviders/mock.ts:24,118`) — cli-agent(단타) 미적용(overhaul PR-3a 리뷰 F-1).

## 3. 범위 (In scope) — A+B+C 확정

### A. 60초 리스크-only 체크 (핵심)
- `tickScheduler` 는 이미 60초 폴링(`POLL_MS`). LLM 5분 틱과 **별개로**, 매 60초 사이클에서 보유
  포지션이 있는 running cli-agent 세션을 **owner-게이트**로 골라 **신선 가격만 조회**해 청산 조건
  (동적 손절선·익절가·하드스톱·장막판)을 검사하고, 걸리면 즉시 EXIT 가상 체결. **LLM 호출 0.**
- 동적 손절선/익절가는 **세션의 최근 틱 decision**(`targetPrice`/`invalidationPrice`)에서 읽는다.
- 슬리피지를 5분 → ~60초로 상한. 다스코류를 −1%대에서 끊는다.
- **LLM 틱과 조율**: 리스크 스윕을 사이클 **먼저** 실행 → 청산되면 그 사이클 LLM 틱은 무포지션으로 봄.
  같은 tickWindow 중복 EXIT 방지(idempotent — 이미 무포지션이면 skip).

### B. 하드스톱 cli-agent 배선
- 포지션 손실률 `≤ positionHardStopPct`(기본 −5%) → 전량 EXIT.
- 세션 수익률 `≤ sessionHardStopPct`(기본 −7%) → 세션 전체 flatten + (기존 대로) 신규 진입 차단.
- A의 60초 경로 + 기존 틱 forced-exit 양쪽에서 검사(mock 경로 무변경).

### C. 하드스톱 % 세션별 설정 (UI)
- 세션 생성 시 **포지션 하드스톱 %** 선택: 보수적 −3 / 표준 −5 / 공격적(눌림목) −8 / **끄기**.
- 세션 필드 `positionHardStopPct?`(+ 선택적 `sessionHardStopPct?`) 추가 — 미지정 시 기본 −5/−7.
- **"끄기" 는 경고 문구 동반**(물타기 무제한 리스크 — 다스코류 −10% 이상 가능). A의 동적 손절선은
  끄기여도 유지(하드스톱만 off).
- 3-tier `riskMode` 와 연동 가능(conservative→−3·balanced→−5·aggressive→−8) + 명시 override.

## 4. 비범위

- 실제 주문/실전(조회·분석 스코프 유지). 순수 엔진·백테스트 라벨링 변경.
- 진입 로직(conviction 컷/사이징)·눌림목 추매 전략 자체 — 별건(overhaul PR-4 데이터 후).
- 체결가 낙관화(스톱 레벨 체결) — 하지 않음(§7 q2). 현실적 슬리피지 유지, **감지 지연만** A로 축소.

## 5. 수용 기준 (AC)

| # | 시나리오 | 기대 |
|---|---|---|
| AC-1 | 보유 중 틱 사이 손절선 하회 | 다음 5분 틱 안 기다리고 A가 ~60초 내 EXIT |
| AC-2 | 포지션 −5% 초과(급락) | B 포지션 하드스톱이 cli-agent 에서 EXIT |
| AC-3 | 세션 −7% 초과 | B 세션 하드스톱 flatten |
| AC-4 | C 세션 설정 −3/−5/−8/끄기 | 각 값이 하드스톱에 반영, 끄기 시 하드스톱 미발동(동적 손절선은 유지) |
| AC-5 | 정상 흐름(급락 없음) | 기존 5분 틱 동작·수익률 무변경(회귀 0), 불필요 EXIT 0 |
| AC-6 | A 리스크 스윕 | LLM 호출 0(가격 조회만), owner-게이트(남 세션 미검사), 중복 EXIT 없음 |
| AC-7 | 관측성 | 손절 EXIT 시 "설정 손절선 vs 실체결가 갭" 을 틱 로그(guardAdjustments)에 기록 |

## 6. 영향 분석

- `tickScheduler` 사이클에 리스크-only 스윕 추가(LLM 5분 틱 앞) — 가격 조회 부하만↑(시세 배치 재사용).
- `virtualExecution.resolveForcedExit` 에 하드스톱 절 추가(cli-agent), 세션 설정값 주입.
- `PaperTradingSession` + Create 요청/검증 + UI 세션 생성 폼(`IntradayWatchTable`)에 하드스톱 % 배선.
- **PR-4 지표 추가**: "손절 후 진입가 회복률"(오늘 스크립트 로직)을 캘리브레이션 대시보드/라벨에 상시화 —
  A의 효과(더 일찍 끊어 회복 못 하는 손실 회피)를 데이터로 추적.
- 가상투자라 금전 피해 0. 안전핀 3단화(동적 손절선 60초 → −5% 포지션 → −7% 세션).
