AI 종목분석 — 12 에이전트 의존성 도식

각 에이전트의 user 프롬프트가 state의 어떤 필드를 실제로 읽는지를 코드에서 추출한 정확한 의존 그래프입니다 (lib/prompts/stock/aiAnalysis.ts + app/api/stock/ai-analysis/route.ts 기준). 실선 = 에이전트→에이전트, 점선 = 공통 입력(사전 계산값). 노드를 클릭하면 그 에이전트가 읽는 것(파랑)과 그 결과를 읽는 에이전트(주황)가 강조됩니다.
입력(사전계산) Phase A 분석가 강세 약세 리서치매니저 트레이더 리스크3 PM(최종)

🔎 "직전 단계만" 이 아니다 — 눈여겨볼 교차(전전 단계) 의존성

  • 트레이더 ← 기술분석가: 리서치매니저 요약만 받는 게 아니라 marketReport(기술분석) 800자를 직접 재참조. 뉴스·펀더멘털·SNS는 직접 안 봄.
  • 리스크 3팀 ← 원시 시그널: 분석가·토론을 건너뛰고 signalSummary(결정론 엔진 원시값) + 리서치플랜 + 트레이더 제안만 읽음.
  • 리서치매니저 ← 토론만: 4개 분석가 리포트를 직접 읽지 않음 — 강세/약세 토론으로 걸러진 것만 받음(+시장 스냅샷).
  • PM ← 거의 전부(최대 fan-in): 4개 분석가 + 토론(강·약세) + 리서치매니저 + 트레이더 + 리스크 3팀 = 11개 에이전트 + 4개 입력을 모두 직접 종합. SNS는 텍스트 + 정형 감성 2채널.
  • 약세 ← 강세(R1): 토론은 순차 — 약세 R1이 강세 R1을 "직접 반박 대상"으로 받음(그래서 R1 병렬화 불가).

❓ 자주 묻는 의문

  • 리서치매니저는 뭘 분석하나? 원자료 재분석이 아니라 토론 심판 + 계획 수립. 강세·약세 논거 전체(+시장 스냅샷)만 읽고 → 6단계 투자 등급 + 진입/청산·목표가·손절·모니터링 포인트가 담긴 실행 계획으로 압축. 4개 분석가 리포트는 직접 안 봄(토론으로 걸러진 것만).
  • 트레이더는 왜 기술분석만 직접 보나? 뉴스·펀더멘털·SNS가 버려지는 게 아니라 간접 전달 — 강세/약세 연구원이 4분석가를 전부 읽고 논거에 녹임 → 트레이더가 그 논거(1500자×2)+RM 계획으로 받음. 기술분석만 raw로 추가하는 건 트레이더 일이 "방향"이 아니라 진입가·손절선·지지/저항 같은 구체 가격 레벨이라 토론 요약에서 뭉개지는 raw 기술이 필요해서. 빠진 펀더멘털 뉘앙스는 PM이 4분석가 raw를 전부 재독해 복구.
