# 로컬에서 토스 모의매매 시작하기

토스 국내주식 시세로 거래량 기준 매매를 연습한다. 새 세션은 브라우저 키에 연결된 직전 종료 자산 또는 최근 수동 저장값을 사용한다. 저장 이력이 없을 때만 1,000만 원으로 시작한다.

## 시작과 종료

1. Node.js 22.9 이상을 사용하고 저장소에서 `npm ci`를 실행한다. `.env.local`에 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`을 설정한다. 다른 네트워크를 쓰면 토스증권 PC 웹에서 허용 IP를 확인한다. [토스 인증 문서](https://developers.tossinvest.com/docs/auth)
2. Supabase 서버 설정을 준비하고 신규 DB는 `docs/sql/program-paper-assets.sql`, 기존 Google 계정 자산 테이블이 있는 DB는 `docs/sql/program-browser-assets.sql`을 적용한다. 로컬에는 Google OAuth·APP_AUTH_SECRET 설정이 필요 없다. `npm run program:dev`로 서버를 켜고 [자동매매 화면](http://127.0.0.1:3000/program-trading)을 연다. 첫 접속에서 브라우저 고유 키가 자동 저장되며 이후 같은 브라우저와 주소에서 이어서 사용한다. `npm run program:check`는 토스 키 설정 여부와 운용 시각을 확인한다.
3. 평일 한국 시간 09:00 이상 15:00 미만에 **토스 모의 시작**을 누른다. 09:05 전에는 후보 조회를 기다린다. 장중에 당일 랭킹을 받을 수 없으면 신규 매수 없이 대기한다.
4. 15:00부터 신규 매수를 중단하며, 5분 점검에서 전체 수익률이 0%를 초과하면 전량 가상 매도 후 종료한다. 0%·음수는 기존 익절·손절로 관리하고 15:30에는 수익률과 관계없이 전량 청산 후 종료한다. 일찍 끝내려면 **매매 종료**를 누른다. 조회 실패·누락·호출 제한으로 청산 가격을 받지 못한 종목은 마지막 유효 기록가로 가상 정산하며, 원장에서 구분한다.
5. 종료 자산의 DB 저장 완료를 확인하고 **새 세션 열기**를 누른다. 계정별 원장과 복기는 `.local/program-trading/accounts/<계정 해시>/toss-paper-archive/`에 보관된다. DB 저장 실패는 30초마다 재시도하며 화면에서도 재시도할 수 있다. 서버 재시작 후 이전 규칙으로 열린 세션은 매매 종료 후 새 세션에서 시작한다.
6. 화면 상단 **자산 설정**에서 다음 시작 자산을 수동 입력한다. 운용·일시정지·청산 중에는 변경할 수 없다. DB 조회 실패 시 기본 금액으로 운용하지 않고 오류를 표시한다. 기존 공용 원장은 계정에 자동 연결하지 않는다.

## 후보 조회와 가상 체결

- 보유 종목이 없으면 토스 국내 시장 실시간 거래량 상위 100개를 조회해 기업 주식(STOCK)으로 확인된 종목만 선정하며 ETF·ETN·파생상품은 제외한다. 거래량 100만 주 이상이고 전일 대비 상승한 종목을 중복 제거한 뒤 거래량이 큰 순서대로 나열한다. 거래량이 같으면 종목코드 순이다. 후보가 없거나 조회에 실패하면 10분 뒤 새 목록을 요청한다.
- 후보가 N개면 조회 시점의 가용 현금을 N으로 나누고, 각 예산 안에서 살 수 있는 정수 주를 랭킹 가격으로 순서대로 가상 매수한다. 1주 미만 배정액과 절사 잔액은 현금으로 남는다. 수수료·세금·슬리피지는 0으로 계산한다.
- 매수 완료 5분 뒤부터 5분마다 보유 종목 전체의 현재가를 한 번에 조회한다. 매수가 대비 +2% 이상이면 전량 익절하고 −1% 이하이면 전량 손절한다. 조회에 빠진 종목은 다음 주기까지 보유한다.
- 보유가 0이 되면 세션 시작 자산과 현금을 비교한다. +1% 이상 또는 −2% 이하이면 종료하고, 그 사이면 다음 조회 가능 시점에 새 후보를 찾는다.

## 토스 호출과 429

브라우저는 로컬 상태를 읽는다. 로컬 서버는 후보 조회에 `/api/v1/rankings`, 보유 가격 조회에 `/api/v1/prices`를 사용한다. 같은 로컬 서버 프로세스에서 두 요청의 전송 간격은 최소 60초다. 토스 OAuth 발급과 다른 화면의 조회는 모의매매의 60초 한도와 별도다. [토스 REST API 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)

429가 오면 해당 요청을 폐기한다. `Retry-After`가 있으면 이후 조회에 반영하고, 후보는 다음 10분 주기, 보유 가격은 다음 5분 주기부터 새 요청으로 확인한다. 개발 서버의 `[toss-rest]` 429 로그는 직전 1·5·60초에 이 프로세스가 전송한 횟수, API 그룹, 호출 출처와 응답 헤더를 보여준다.

현재 원장 버전은 `program-v7-afternoon-close`이다. 이전 결과는 기존 규칙으로 읽을 수 있다. 화면의 **매매 기준 보기**에서 전체 호출 흐름과 매수·매도·정산 다이어그램을 확인한다.

## 다이어그램 브라우저 검사

`npm run program:rules:check`로 다이어그램과 생성 원본의 일치를 확인한다. 실제 Chrome 렌더링을 검사할 때는 macOS 일반 터미널에서 `npm run program:rules:browser`를 실행한다. 기본값은 요약이고, `npm run program:rules:browser -- buy`처럼 `detail`, `buy`, `sell`, `settlement`를 지정할 수 있다.

2026년 11월 24일에는 제한된 Codex 셸이 띄운 검사 전용 Chrome 프로세스가 macOS 앱 등록 중 종료됐다. 동일한 다이어그램은 셸 제한 밖에서 통과했다. 브라우저 검사 명령은 제한된 macOS Codex 셸에서 Chrome을 띄우기 전에 종료한다.

## 결과 저장과 Codex 복기

연결된 Supabase 프로젝트의 SQL Editor에서 [program-paper-reviews.sql](../sql/program-paper-reviews.sql)을 한 번 실행한다. 기존 AI 단타 모의투자 테이블과 별도로 생성되며, 서버 키만 읽고 쓸 수 있다. 기존 `SUPABASE_URL` 또는 `NEXT_PUBLIC_SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY` 설정을 사용한다.

`.env.local`에 `PROGRAM_PAPER_RESULT_SYNC=1`을 추가하고 개발 서버를 다시 시작하면 새 종료 결과를 로컬 원장에 기록한 뒤 백그라운드에서 저장한다. DB가 일시적으로 실패하면 로컬 파일을 기준으로 `sync`를 재실행한다. `sync`를 반복해도 같은 결과는 중복 생성되지 않는다.

| 작업 | 명령 |
| --- | --- |
| 로컬 결과와 보관 ID 확인 | `npm run program:review -- local` |
| 가장 최근 완료 결과 또는 보관 세션 업로드 | `npm run program:review -- sync` 또는 `npm run program:review -- sync <보관ID>` |
| DB 결과 목록 | `npm run program:review -- list` |
| 로컬 Codex CLI로 평가하고 점수·근거·제안 추가 | `npm run program:review -- score <세션ID>` |
| 실제 변경을 커밋한 뒤 적용 기록 추가 | `npm run program:review -- applied <세션ID> <커밋SHA> "적용 내용"` |
| DB 결과와 평가·적용 이력 조회 | `npm run program:review -- show <세션ID>` |

`score`는 `codex login status`로 로그인 상태를 확인한 CLI를 실행한다. Codex에는 저장된 복기 보고서가 전달된다. 평가는 원장·비용 대사(40점), 규칙 준수 확인(30점), 시세 품질과 종료 검증(30점)을 기준으로 한다. 점수와 제안은 평가 시점별로 남으며, 규칙 변경은 실제 작업과 검증 후 적용 내역으로 기록한다. 목록과 이력은 최근 20건부터 표시하며, `list 20` 또는 `show <세션ID> 20`으로 다음 페이지를 조회할 수 있다.

실행 PC와 조회 PC의 서버를 같은 Supabase 프로젝트에 연결한다. 조회 PC에서는 토스 키 없이 [모의매매 결과](http://127.0.0.1:3000/program-trading/review?source=shared)를 열 수 있다. 자동매매 → **세션 결과 보기** → **공유 DB 결과**에서도 종료 결과와 AI 평가·개선 이력을 볼 수 있다. 배포 환경에서는 관리자 계정으로 **마이페이지 → 관리자 메뉴 → 자동매매 모의 결과**를 연다. 자동 저장 설정을 켜기 전에 종료한 세션은 실행 PC에서 위의 `sync` 명령으로 등록한다.

**개선 적용하기**는 선택한 세션의 최신 Codex 평가에서 근거가 있는 개선 한 가지를 골라 작업 폴더에 반영한다. 현재 운용을 종료하고 버튼을 누른다. Codex CLI 로그인과 Archify 설치가 필요하다. Archify 기본 경로가 다르면 `.env.local`에 `ARCHIFY_HOME`을 지정한다. 검증을 통과하고 적용이 완료되면 로컬 개발 서버를 다시 시작한다. 적용된 작업은 커밋 전에 Git diff로 확인할 수 있다.

후보는 토스 기본정보의 `securityType=STOCK`인 기업 주식만 허용한다. ETF·ETN·파생상품과 유형 미확인 종목은 제외하며 기본정보 조회 실패 시 신규 매수하지 않는다.
