# 한투 실거래 연동 · 현재 운용 방법

2026-11-01 후속 구현 기준. 아래 과거 기록의 합성 전용 제한은 `PROGRAM_TRADING_MODE=replay`에만 해당한다.

## 실행

1. `npm run program:dev`로 로컬 웹과 상시 워커를 함께 실행한다. `/program-trading`에서 계좌 환경·연결 계좌·매수 한도를 확인한다.
2. 계좌 앞 8자리·상품코드·Open API 키로 연결한다. 기존 서버 KIS 키가 같은 계좌 환경이면 입력을 생략할 수 있다. 비밀번호는 수집하지 않는다. 검증된 값은 `.env.local`의 `PROGRAM_KIS_*`에만 보관한다.
3. 기본 운용은 연결한 계좌 환경이다: `prod`는 실제 주문, `vts`는 한투 모의주문이다. 합성 리플레이는 `PROGRAM_TRADING_MODE=replay`를 명시해야 한다. 계좌 연결·페이지 열기·워커 실행만으로 매수하지 않는다.
4. 한국 거래일 09:10~15:00 미만에 시작 버튼을 누른다. 기존 보유·미체결 없는 현금 계좌가 필요하다. 기존 자산은 자동 청산하지 않는다. 휴장/장외·잔액·대사 문제는 시작 전에 표시한다.
5. 종료 버튼은 신규 매수를 차단하고 매수 미체결 취소 확인→세션 보유분 매도→주문·잔고 대사 후 완료한다. 워커 프로세스를 강제 종료하는 것은 청산 버튼과 다르다. 포지션이 남으면 워커를 유지해야 위험관리를 계속할 수 있다.

## 한도·시간·데이터

- 매수는 현금 가능 수량 안에서 지정가, 매도는 시장가. 기본 매수 1회 한도는 1,000,000원(`KIS_ORDER_MAX_KRW`로 변경). 매도 체결 가격은 보장하지 않는다. `KIS_DRY_RUN=1`이면 주문을 차단하며 가짜 체결을 만들지 않는다.
- 최대2종목, 종목당 자산20%, 거래 위험0.25%, 손절1%·익절2%, 계좌 자산손실2% 잠금, 15:20 청산 정책. 실제 비용은 계좌의 일별 제비용과 대조하고 정산 차이1원 초과면 확정을 보류한다.
- 후보는 거래량10·외국인10·기관10 합집합, 60초 갱신/120초 만료. 한투 순위·휴장 조회는 실전 시세 키가 필요하다. VTS 계좌는 별도 실전 시세용 `KIS_APP_KEY`/`KIS_APP_SECRET`를 사용한다. 미지원 API를 가상 데이터로 대체하지 않는다.
- 실제 완료3분봉과 진행분 거래량, 최근 체결시각·호가시각, 거래정지·장상태를 확인한다. 진행분 고가는 이전3분 고가에 포함하지 않는다. 매 점검은 보유분 우선 + 순환 후보1개로 API 지연을 제한한다.
- Next/Vercel 서버리스에서 지속 매매를 실행하지 않는다. 계좌 API와 워커는 로컬 개발 환경의 loopback에만 연결된다. 화면을 닫아도 워커가 실행 중이면 운용한다.

## 원장·복기·복구

- 계좌별 `.local/program-trading/live/<계좌해시>/live.jsonl`에 주문 의도·접수·체결·취소·상태를 append+fsync한다. API 키/시크릿은 원장에 포함하지 않는다. 같은 포트의 워커는 하나만 실행한다.
- 주문 의도 저장 후 단1회 전송한다. timeout/주문번호 누락은 결과 불명으로 잠그며 자동 재전송하지 않는다. 부분체결은 누적수량·금액 차분만 기록한다. 매수 미체결은30초 후 취소 요청하며 취소가 확인되기 전 잔량을 다시 주문하지 않는다.
- 워커 재시작은 원장 복원→전체 페이지 주문·잔고 대사→신규 매수 중지 상태다. 종료 중 청산과 위험관리는 확인된 세션 보유분에 한해 계속한다. 완료 후 다음 거래일에는 새 세션을 만들고 과거 원장은 보존한다.
- 주문번호를 받지 못한 주문은 자동 추측 연결하지 않는다. 운용자가 한투에서 실제 주문번호를 확인한 경우 워커를 종료한 후 `npm run program:resolve -- --client-id=<원장 의도ID> --broker-order-id=<확인한 주문번호> --date=YYYYMMDD --confirm-broker-order=yes`로 연결 기록을 남길 수 있다. 이 명령은 주문·취소를 보내지 않는다. 재시작 후 잔고 대사를 거치며 신규 매수는 자동 재개하지 않는다.
- 종료 후 `review.json`/`review.md`에 실제 전후 계좌자산·수익률과 전체 체결을 기록한다. 목표 기본1% 이상이면 keep로 개선 제안을 생략한다. 미달이면 검토 가이드만 생성하며 자동 코드 변경은 없다. 입출금·수동매매·비용 불일치가 있으면 성과 확정과 목표달성 판정을 보류한다.
- `npm run program:check`는 잔액/당일 주문/휴장일의 조회 전용 검사다. 실제 주문·취소는 호출하지 않는다.

## 검증 한계

실제 계좌에서 잔액·일별 제비용·당일 주문 조회 완료·휴장일 응답을 확인했다. 휴장일이므로 실제 접수·부분체결·취소·장중 시세·최종 정산은 브로커 fake와 응답 fixture 테스트로 검증했다. 실제 주문은 전송하지 않았다. 실거래 성과나 장기 무장애 운용을 보장하는 검증은 아니다.

# 한투 후보 조회·갱신 연동

## 2026-10-29 적용

기존 KIS 조회 API를 재사용한다. 후보는 실제 조회이며 매매용 시세·체결은 합성 모델이다.

- 거래량 순위 보통주 최대 10개 + 외국인 순매수 10개 + 기관 순매수 10개, 중복 제거.
- 워커 시작 및 운용 시작 명령에서 조회. 별도 타이머로 60초마다 갱신.
- 외부 조회는 매매 직렬 대기열 밖에서 수행. 결과 적용과 저장만 직렬화하므로 네트워크 응답을 기다리는 동안에도 보유분 점검 가능. 파일 저장 지연까지 분리한 것은 아니다.
- 중복 갱신은 진행 중인 요청 하나로 합침. 시작 조회 중 중지·청산 명령이 들어오면 이전 시작 명령 취소.
- 한 조회라도 실패하거나 후보가 없으면 신규 매수 중지. 120초 만료 검사 유지. 회복 후 자동 시작 없음. 후보에서 제외된 보유분 위험관리 유지.
- 후보의 최신 가격은 목록에 반영되지만 합성 시세 기준가는 종목 최초 편입 시 고정하는 기존 정책 유지.

## 실행에 필요한 설정

기존 `.env`/`.env.local`의 `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ENV=prod` 사용. 로컬에 이미 설정되어 있어 추가 키 입력은 필요하지 않았다. 키·토큰은 문서나 HTML에 기록하지 않는다.

`npm run program:worker`와 `npm run dev` 실행 후 `/program-trading` 전용 메뉴에서 후보·조회 상태 확인. 코드 변경을 적용하려면 기존 워커 재시작 필요. 재시작은 신규 매수 중지 상태로 복원한다.
